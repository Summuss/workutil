# Evidence 页里有一个 memo 侧栏,但那不是模型耦合

做 evidence 的时候经常要照着一条 memo 核对(上次改的是哪个文件、报错长什么样、这个用例本来要验什么),也经常要从 memo 里拿一段字贴进去。原来只能离开 evidence 去 memo 页,回来就得从 evidence 列表重新走一遍。现在 **evidence 详情页右侧有一个可收放的 memo 侧栏**。

[ADR-0001](./0001-memo-and-evidence-are-separate-concepts.md) 说 Memo 与 Evidence 是两个独立概念,只共享图片的存储机制。这条 ADR 存在,是为了让下一个看到这个侧栏的人不必去怀疑那一条:**侧栏是视图层面的共处,不是模型层面的耦合**。它读 memo 现成的列表/搜索接口,不建立任何数据关系 —— 没有「这份 evidence 关联了哪几条 memo」,没有反向引用,两边的表一列也没多。ADR-0001 划的线没有被越过。

## Considered Options

- **命令面板式浮层**(`Ctrl+K` 呼出,搜完即走):不占版面,和 [ADR-0007](./0007-fixed-viewport-shell.md) 零冲突。**落选**,因为它服务的是「进去拿一段字就走」,而更常见的场景是**边看边核对** —— 那要求两边同时可见,浮层盖上去正好盖住要核对的东西。
- **什么都不做,靠浏览器前进后退**:case 进 URL 之后,「去 memo 看一眼再后退」确实回得到原处。**落选**,理由同上:后退能解决「位置丢了」,解决不了「要同时看着两样东西」。

## Consequences

- **侧栏只读。** 搜索、展开看正文、选中复制,没有编辑/删除/置顶,也不能新建 memo。理由有两条:一是[草稿](../../CONTEXT.md)那一套(角标 / 放弃 / 跨刷新)会不得不在侧栏里再活一份;二是删除和置顶挤在一条窄栏里是纯粹的误触陷阱。「做 evidence 时想起一件事,随手记一条」是个真实需求,但它是**下一步**,不是这一步。
- **不给「插入到当前用例」按钮。** 它插进去的是整条 memo 正文,而实际要的多半只是其中一行(一个 ID、一句 SQL)。插完还要再编辑一遍,比选中复制更慢。
- **宽度固定 360px,不可拖拽。** ADR-0007 那套固定外壳本来就在拒绝「让用户自己调布局」;固定宽度还让「截图被挤掉多少」成为一个确定的数,而不是一个说不清的变量。
- **开着时 evidence 内容区被挤窄,不是被盖住、也不是被推出视野**(推开会带来横向滚动,ADR-0007 明令禁止)。侧栏占满整个内容区高度,标题行和用例标签栏一起变窄 —— 用例栏本来就是 `overflow-x-auto`,压窄只是让它早一点开始横滚;而只占 block 列表那一段的话,侧栏顶部的搜索框会悬在页面中段,那才是固定外壳一直在避免的观感。
- **因此 evidence 的截图必须能点开看原图。** 侧栏一开截图只会变小,而在此之前 evidence 的图是一个裸 `<img>`,没有任何放大的路(`Lightbox` 只接在 memo 的 Markdown 上)。这笔代价和侧栏是同一次改动造成的,所以一起付,不留到 backlog。
- **快捷键是 `Ctrl+M`,且只认 `ctrlKey`,不认 `metaKey`。** 这是全项目第一个破掉「`ctrlKey || metaKey` 一起认」那条惯例的手势 —— macOS 上 `Cmd+M` 是系统级的「最小化窗口」,抢不过来。代码里要有一行注释说明为什么破例,否则它看起来只是漏写了一半。
- **开合状态记在 localStorage**,和语言、memo/todo 的展开状态同款。宽度不记(它不可变)。
- **只在 evidence 详情页。** 不铺到 Todo、书签页 —— 侧栏在 evidence 上是有理由的,在别处还没有;requirements.md §5 的第一约束是「新增一个功能不应改动既有功能」。
