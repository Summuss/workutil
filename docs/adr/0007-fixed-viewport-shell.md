# 界面外壳固定一屏,放弃浏览器原生滚动

页面自然变长、整窗滚动,是网页的默认形状,也是这个工具最初的形状(`min-h-screen` + 高度跟着内容走的 `<main>`)。实际用下来它一直在晃:展开一条带截图的 Memo 会让整页高度暴涨、折叠又缩回去,切换 Evidence 用例时内容区先塌成一行 loading 再撑开,书签页弹出一条提示就把下面所有东西推下去。**每一次内容变化都是一次布局跳动**,而这个工具的每个页面都在频繁地展开、折叠、切换、增删。

所以外壳改成**固定一屏高**(`h-dvh overflow-hidden`),导航条不参与滚动,滚动下放到每个页面自己的内容区,由各页决定哪部分钉住、哪部分滚。

## Consequences

- **失去了浏览器原生滚动的一些东西。** 窗口滚动条没有了;`Ctrl+F` 的浏览器内查找只能命中滚动容器里已渲染的部分;`Home`/`End` 的行为取决于焦点落在哪个容器里。都接受 —— 找东西在这个工具里走的是 Memo 的搜索框,不是浏览器查找。
- **每一个「要滚的 flex 子项」都必须显式写 `min-h-0`。** flex 子项的 `min-height` 默认是 `auto`,漏一个,内容就会把容器撑破、滚动条又长回窗口上,而且症状看起来像「这次改动没生效」。这是这套布局唯一的常驻陷阱。
- **拖拽必须用 `DragOverlay`。** 内容区成了 `overflow` 容器,原地位移的拖拽元素会在容器边缘被裁掉。跨容器拖拽(书签跨组)在这个前提下不用浮层根本做不了。
- **单条内容仍然可以自己吃掉一屏**,固定外壳治不了这个。所以 Memo 里的图片改成了高度上限 200px 的缩略图 + 点击看原图 —— 那是这条决定的配套,不是独立的偏好。
- 一律不做响应式断点。两台目标机器都是桌面浏览器全屏使用(requirements.md §2),固定一屏在窄窗口下的取舍不在考虑范围内。
