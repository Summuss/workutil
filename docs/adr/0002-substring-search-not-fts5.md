# Memo 搜索用 LIKE 子串匹配,不用 FTS5

SQLite 的 FTS5 全文索引是这个场景的显然选择,我们**刻意没有采用**。实测(SQLite 3.45.1)其两种分词器对中日文都不可用:默认 `unicode61` 把一整串 CJK 字符视作单个 token,查 `中文` 匹配不到 `中文分词`;`trigram` 分词器要求查询至少 3 个字符,而中日文常用词大量是两字(バグ、対応、修正、中文),同样查不到。

改用 `LIKE '%q%'` 子串匹配:中日英全部命中,且实测一万条 Memo(约 283 万字符)最坏情况(无命中、全表扫描)仅 **8ms**,对个人工具的数据量绰绰有余。

## Consequences

看到 `LIKE '%q%'` 时不要「优化」成 FTS5 —— 那会静默破坏中日文搜索,而英文测试用例发现不了。若将来数据量真的大到扫不动,正确的方向是引入 jieba / MeCab 之类的分词器再配 FTS5,而不是直接切换分词器。
