# 书签是第二条任意代码执行链,知情接受

design.md §6 F4 曾写着「服务只绑定 `127.0.0.1`。**这是本设计中唯一具备任意代码执行能力的部分**」。F3 书签一落地,这句话就不再成立:一个指向 `.bat` / `.exe` / `.command` 的书签,点一下就是执行 —— 而且是**后端代为执行**的(`os.startfile` 会按系统关联启动它)。

我们**不限制书签能指向什么**,而是把那句话改对。

限制的选项都试着想过:扩展名黑名单(`.bat/.cmd/.exe/.ps1/.sh/.command`)、或登记时加一次额外确认。都不采用:

- **威胁模型对不上。** 真正的防线是「只绑 `127.0.0.1`」加上「没有任何外部内容能触发这些接口」。书签是用户**一条条亲手粘进来的本机路径**,不像 memo 正文那样来自外部粘贴 —— F1 禁用 raw HTML 防的是「页面里的脚本去调本机后端」那条链,和这里不是一条路径。黑名单挡不住那条链(它根本不从这里过),只挡得住用户自己。
- **它挡掉的正是真实用途。**「一键跑那个部署 bat」就是这个功能会被用到的方式之一。
- **额外确认会自我废除。** 一个平时用不到的确认按钮,只会训练人闭着眼睛点它。

## Consequences

- design.md §6 F4 里「唯一」那句必须改掉,并明确指出书签是第二条。**一句会误导后来者(尤其是 AI agent)的假话,比没有这句话危险得多** —— 它会让人以为这条链不存在,从而在别处放松真正该守的东西。
- 这条决定是**知情接受**,不是没想到。若将来要收紧(比如工作机的安全策略要求),该动的是**绑定地址与进程权限**,不是给书签加扩展名黑名单;后者只是让人觉得安全。
- 已经登记的书签会因为收紧而失效,所以反悔的代价不只是改代码。
