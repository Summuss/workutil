# Memo 可以置顶,但仍然不可分类

requirements.md §7 把「Memo 标签归类」明确推迟了,理由是**归类本身就是录入负担**,与 Memo 存在的意义(极低摩擦地记下来)直接冲突。而现在 Memo 有了置顶。看起来像是那条决定被推翻了,不是的 —— 两者的差别值得写下来,否则下一个看到置顶的人会顺理成章地想「那加个标签也一样吧」。

**置顶是「这条现在常用」这一个比特。** 它没有维度(不需要想「按什么分」)、没有名字(不需要起一个)、发生在事后(记的时候完全不用管)、随手可开可关。标签则要求在**记录的那一刻**做一个分类决定,而那一刻正是要保护的。所以置顶不构成录入负担,标签构成 —— 推迟标签的那条理由在置顶身上不成立。

## Consequences

- **CONTEXT.md 里「Memo 无序」这条定义让步了**,改成「除置顶外无序」。这是这个决定真正的代价:词汇表里少了一条干净的断言。
- **置顶不复用 `core/ordering.py` 的 `Ordered`。** 那套东西表达的是「这批东西之间的先后关系」,是 Todo / Bookmark / Case / Block 领域含义的一部分;memo 之间没有这种关系。置顶存成一个 `pinned_at` 时间戳(非空即置顶,值同时就是置顶区内的顺序),**memo 表没有 `order` 列** —— 加上它就等于承认 memo 之间有秩序,那才是真的推翻了定义。
- **置顶只作用于默认列表,搜索时不生效。** 置顶解决「常用的不用找」,搜索解决「知道关键词但不知道在哪」,两种意图互斥。让置顶在搜索里也生效,会让「结果按时间倒序」这条唯一的排序规则出现例外。
- **置顶必须是一次单独查询。** 列表接口只取最近 200 条(`RECENT_MEMO_LIMIT`),一条钉住的旧 memo 会落在那之后 —— 而「钉住一条三个月前的」恰恰是这个功能最主要的用法。混在同一次查询里排序会让它悄悄失效。
- 不设置顶条数上限。自用工具,钉多了自己会取消。
