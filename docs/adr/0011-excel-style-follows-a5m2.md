# Evidence 的 Excel 样式以 a5m2 粘贴结果为基准

requirements.md §3 写着「Evidence 的 Excel 格式**自由格式**,由工具自己定」,理由是「目前没有公司指定模板」。那句话只对了一半:**没有公司模板,不等于没有基准。**

真正的基准是**既存的 evidence 文件**。它们全都是把 A5:SQL Mk-2 的查询结果复制、粘贴进 Excel 手工做出来的。工具生成的那几份和手工做的那几份会并排出现在同一批交付物里 —— 字体不同、表头的换行方式不同、NULL 的颜色不同,看起来就是两个人做的两份东西。而 evidence 是交给别人验收的材料,「看起来像同一批」本身就是它的质量之一。

所以基准从「工具自己定」换成**「和从 a5m2 粘进 Excel 的结果一致」**。表头底色 `#87e7ad` 当初就是为这个定的,只是当时没写下来为什么;这条 ADR 把那个理由补上,并把范围扩展到字体、表头排版与 NULL 的呈现。

## Consequences

- **`LayoutSettings` 里的值从此有了外部依据,不能凭手感改。** 改之前要能说出「a5m2 粘出来就是这样」。这是这条决定真正的代价:少了一处可以随便调的地方。
- 具体对齐四项:字体 `游ゴシック` 11;表头 `wrap_text` + 垂直居中,数据行不设 alignment(长值被右邻格截断,不折行);单元格值恰为 `≪ NULL ≫` 时字体色 `#808080`;表头底色 `#87e7ad` + 加粗(本来就是)。
- **列宽 18 是明确的例外。** a5m2 粘贴根本不设列宽 —— Excel 里看到的是它自己的默认值(8.38 字符),不是 a5m2 的选择,所以这一项上「和 a5m2 一致」没有对象。18 是 workutil 为「同一个 sheet 里图片和表格共存」定的,窄回默认值受损的是截图那半边。
- **NULL 的判定是精确字符串比对**:`≪ NULL ≫`(U+226A + 空格 + `NULL` + 空格 + U+226B),不 trim、不认 `«NULL»` 一类变体、不用正则。理由和 ADR-0004 的 `@` 格式同源:evidence 的底线是「我看到的就是这个值」,而数据里真实存在一个长得像 NULL 的字符串是可能的。**宁可漏判,不可错判。**
- **字体在 xlsx 里是按名字存的**,渲染取决于打开它的机器。日文 Windows 一定有 `游ゴシック`,macOS 装的是 `YuGothic` / `游ゴシック体`,名字对不上时 Excel 会自己回退 —— 在 Mac 上预览和工作机上不一样是已知的、接受的偏差,因为交付对象是工作机那边。
- 字体、颜色、bold 全部经由 `layout.py` 的 `_text_cell` 这一个漏斗设置。它已经是「每一格都要经过」的地方(剥控制字符、摁住 `data_type`),字体属于同一类「每格都要做的事」。**不改 openpyxl 的 `Normal` 命名样式** —— 那是半私有 API,升级时会静默变。
- ADR-0004 的 `@` 文本格式不受影响,反而被加强:图里那些「以文本形式存储的数字」绿色三角,正是 a5m2 粘贴出来的样子。
- **这条决定什么时候失效**:公司真的给了模板(那时基准换成模板),或者数据不再从 a5m2 来(那时它就只是历史包袱,该删)。
