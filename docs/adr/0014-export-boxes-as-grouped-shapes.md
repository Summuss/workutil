# 红框导出成 Excel 里的四边形,和截图编成一组

截图上的[红框](../../CONTEXT.md)在工具里是 image Block 上的数据,原图一个字节不动。导出时它要变成 **Excel 原生的四边形**(无填充、红、2.25pt),而且**和截图编成一组**:组的坐标就是截图自己的坐标,框在组里按原图的比例摆。交付出去的文件里,框点得中、拖得动、删得掉 —— 和手工做的 evidence 一样,那正是这一条的要求。

openpyxl 写不出形状(`SpreadsheetDrawing._write` 只遍历 `charts + images`,`GroupShape` 只装得下一张 `pic`)。所以工作簿照常 `wb.save`,之后改写 `xl/drawings/drawingN.xml` 把组和四边形补进去。[ADR-0004](./0004-table-is-a-first-class-block.md) 为一个绿色三角说过「拆 zip 手改 XML,不值得」—— 那是代价对不上收益;这里是交付形态本身的要求,而且没有别的路,所以代价要付。

## Considered Options

- **把框画进导出的那份图片里**(几行 Pillow):最省事,原图照样不动。**落选**,因为交付后框在 Excel 里就只是像素了,挪不动也删不掉,而要求就是交付后还能改。
- **每个框单独摆**(一个 `oneCellAnchor` 一个框,行按 20px 的预留行换算,列钉在 `A` 列、`colOff` 超出 `A` 列宽):点一下就选中,和手工画的一模一样。原型(分支 `prototype/evidence-annotation-shapes`)在 macOS 的 Excel 和 Excel 网页版上实测也对得上。**落选**,因为它对得上靠的是 Excel 怎么读「比单元格还宽的偏移」,而工作机的 Windows 桌面版没实测过;编组则由格式本身保证对齐,和行高列宽无关 —— 后两者正是会随 Windows 显示缩放变的东西(预留行在 125% 下变矮就是这么来的)。用户把两种都试过之后选了编组。
- **按列宽把 x 拆成「第几列 + 列内偏移」**:列宽换算成像素用的是默认字体的数字宽度,会随显示缩放变,而且没有 `customHeight` 那样的办法钉死。没进原型。

## Consequences

- **在 Excel 里要点两下才选中单个框**:第一下选中整组,第二下选中框。用户试用后接受。
- **挪截图,框跟着走。** 调整版面时框不会留在原地标着一片空白。
- 交付物里的形状是**组**,不是手工那样散着的四边形;要散开就在 Excel 里「グループ解除」。
- 导出多了一步改 XML。它只碰带框的截图所在的 drawing,一个框都没有的工作簿原样返回;红框的颜色和线宽在 `LayoutSettings` 里,和其他排版参数放在一起。实现要点(sheet 与 drawing 怎么对上、比例为什么横纵分开)见 design.md §6 F5「截图上的红框」。
