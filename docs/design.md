# workutil 技术设计

> 本文描述**怎么实现**。需求背景与功能定义见 [requirements.md](./requirements.md)。

## 1. 架构判断

**形态:本地 Python 服务 + 浏览器 Web UI,只监听 `127.0.0.1`。**

推导过程:

1. **F3 / F5 都必须访问「用户当下正在用的那台电脑」的本地资源** —— 打开本地文件、读本地剪贴板截图、写本地 Excel。
2. 因此工具**不能只部署在家里的 Linux 服务器上、用浏览器远程访问** —— 那样操作的是服务器的文件和剪贴板,而不是工作机的。它必须作为本地应用分别运行在 Windows 和 macOS 上。
3. 而开发又在**无桌面的 Linux 服务器**上进行,意味着 UI 必须能在浏览器里开发调试(SSH 端口转发到 macOS),不能依赖本机 GUI 窗口。

两个约束叠加,指向「Web UI + 本地后端」。后端选 Python 是因为**最难的需求恰好落在 Python 生态最成熟的地方**:F5 的 Excel 嵌图靠 openpyxl、图片处理靠 Pillow。

> F4(Python 脚本管理与执行)当初也是选 Python 后端的理由之一 —— 本来就要跑 Python。它已推迟(见 requirements.md §7),下面 §2 和 §3.3 里带 F4 的条目都是**为它预留、尚未实现**的设计,不是已落地的行为。

> 曾考虑 Electron(分发体验最好,但无桌面服务器上无法直接调试,且 Excel 嵌图用 exceljs 比 openpyxl 麻烦)与 Tauri(体积最小,但要写 Rust,且 macOS 版必须在 macOS 上构建)。均因与上述约束冲突而未采用。

### 这个选择的代价

浏览器标签页**无法注册全局快捷键**。因此 F1 的实际录入路径是「切到浏览器 → 找到 workutil 标签页 → 输入」,未必快过一直开着的记事本 —— 而「极低摩擦」正是 F1 的核心卖点。

**这是当前架构最大的产品风险,且尚未被真实使用验证。** 第一版接受它,在浏览器形态内把摩擦压到最低(单页、打开即聚焦输入框、`Ctrl+Enter` 保存,零导航点击)。若真实使用一周后仍觉得慢,补一个极小的原生入口(系统托盘 + 全局热键,只负责唤起并聚焦)即可,那是增量而非重做 —— 所以现在不值得为它推翻整个形态。

## 2. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | FastAPI + uvicorn | F4 需要 SSE 流式输出脚本日志,异步是刚需 |
| 前端 | React + TypeScript + Vite | 服务器已有 Node 22 / pnpm 10 |
| 路由 | react-router | M2 起不止一个功能,且 Evidence 有三级导航(列表 → 某份 → Case)。URL 即状态,浏览器前进后退可用 |
| 样式 | Tailwind CSS | |
| Markdown 渲染 | react-markdown + rehype-highlight | F1 展开正文。**默认不解析 raw HTML**,这正是 §6 F1 那条安全要求要的行为,不必再叠一层消毒 |
| 代码编辑器 | CodeMirror 6 | F4 脚本编辑。比 Monaco 轻得多,够用 |
| 数据库 | SQLite + SQLAlchemy 2.0 + Alembic | 功能会陆续增加,schema 一定会变,迁移能力从一开始就要有 |
| 图片存储 | 磁盘文件,DB 只存相对路径 | 截图体积大,存 BLOB 会撑爆 DB 且难备份 |
| Excel | openpyxl | 图片嵌入与定位是它的强项 |
| 图像处理 | Pillow | 缩略图、格式转换、尺寸计算 |
| 路径 | platformdirs | 跨平台数据目录 |
| 多语言(i18n) | 自研极简(React Context + JSON 语言包) | 只需中日两种,不需要复数规则、插值、命名空间这些库要解决的问题,react-i18next 相对现在的规模是过度设计 |

## 3. 影响全局的决定

### 3.1 生产环境由 FastAPI 直接托管前端构建产物

前端构建在开发服务器上完成,产物交给 FastAPI 作为静态文件托管。

**这样工作机上只需要 Python,不需要 Node。** 直接减少一半的环境依赖 —— 在「工作机能否装软件」尚未确认的情况下,这是重要的风险对冲。

托管不是「按文件找,找不到就 404」那么简单:前端走真实路径而非 hash 路由,在 `/evidence` 上按 `F5` 会向后端要一个不存在的文件。这类路径必须回 `index.html`,前端路由才有机会看到这个 URL。带扩展名的路径与 `/api` 下的路径**保持 404** —— 一个失效的 `<script src>` 拿到 HTML,错误会报在 MIME 类型上,比 404 难查得多。实现见 `main.py` 的 `SinglePageApp`。

### 3.2 用 `uv` 管理 Python 环境

`uv` 是单文件二进制,并且能自己安装 Python。万一工作机不允许安装软件,这是最好的退路;届时再用 PyInstaller 打包成免安装版也不必改动架构。

### 3.3 平台操作收敛到一层抽象

`core/platform.py` 只有两个动词:

- `open(path)` —— 把路径交给系统,之后不再关心。**文件和文件夹共用这一个**,因为在两个平台上它们本来就是同一个调用
- `reveal(path)` —— 在文件管理器里定位到它

| 操作 | Windows | macOS |
| --- | --- | --- |
| `open` | `os.startfile(path)` | `open <path>` |
| `reveal` | `explorer /select,"<path>"`(整条命令行手工拼,引号只包路径,路径先过 `PureWindowsPath` 转成反斜杠) | `open -R <path>` |

`reveal` 的 Windows 侧不能用参数列表:explorer 自己解析命令行,路径一带空格,`list2cmdline` 就会把整个 `/select,...` 包进引号,而 explorer 读不懂这种形式时**不报错,直接打开「文档」文件夹**。路径用正斜杠写的书签同理。

**F4 的「执行脚本」不进这一层。** 那是 `subprocess` + 流式输出 + 进程句柄,和「交出去就不管」是两种东西,硬共用一个抽象只会让两边都别扭。

**Linux 实现明确「不支持」,直接抛错,不调 `xdg-open`。** 开发服务器没有桌面,而 `xdg-open` 在无 `DISPLAY` 的机器上失败得很脏 —— 有时退出码 0 却什么都没发生。把它当「支持」等于让开发时的每一次验证都在撒谎。明确不支持反而有用:UI 上那条错误路径**因此在服务器上每天都会被真实走到**,而它恰好是这个功能里唯一能在服务器上验的部分。

平台层经 `deps.py` **注入**,于是 HTTP 主接缝里换得成一个记录调用的 fake:「点这条书签 → 平台层收到了这个路径」「一键开组 → 按 `order` 收到了这 7 条、失效那条没传下去」都有自动化覆盖。真机上要验的因此收缩成一句「系统真的开了那个窗口」。

这既是跨平台的需要,也**把「在服务器上无法验证」的风险圈进一个可替换的小范围**(见 §7)。

### 3.4 界面外壳固定一屏,滚动下放到内容区

外壳是 `h-dvh overflow-hidden`:导航条 52px 不参与滚动,`<main>` 是 `flex-1 min-h-0` 的滚动容器。**滚动的是内容区,不是窗口**。每页再自己划一条线,把高频操作的输入区钉住(Memo 的输入框与搜索栏、Evidence 的标题行与用例标签栏 + 底部的粘贴框、书签与 Todo 的操作按钮行),列表部分滚。四页内容不设最大宽度,铺满窗口,左右各留 `px-8`(32px)的余白 —— 与导航条同一条 gutter,页面之间的左右边界因此仍然对齐。

理由是 requirements.md §5 那条「界面稳定」:页面自然变长是网页的默认形状,但这个工具的每个页面都在频繁展开、折叠、切换、增删,默认形状下**每一次内容变化都是一次布局跳动**。代价(失去窗口滚动条、`Ctrl+F` 只能命中已渲染部分)记在 [ADR-0007](./adr/0007-fixed-viewport-shell.md)。

两个必须知道的连带后果:

- **每一个「要滚的 flex 子项」都要显式写 `min-h-0`。** flex 子项的 `min-height` 默认是 `auto`,漏一个,内容就把容器撑破、滚动条又长回窗口上,而症状看起来像「这次改动没生效」。这是这套布局唯一的常驻陷阱。
- **拖拽必须用 dnd-kit 的 `DragOverlay`。** 内容区成了 `overflow` 容器,原地位移的拖拽元素会在边缘被裁掉;跨容器拖拽(书签跨组)在这个前提下不用浮层根本做不了。

固定外壳治不了「单条内容自己吃掉一屏」,那由 §6 F1 的图片缩略图解决。

### 3.5 便携包分发与独立窗口

工作机可以在任意位置执行程序但不能自由安装运行环境,且只能匿名访问 GitHub(见 requirements.md §6)。因此分发形态定为**解压即用的便携 zip 包**,通过 GitHub Release 发布。

#### 包的形状与在 Linux 上的组装

不使用 PyInstaller(它无法交叉编译,而在无桌面 Linux 开发服务器上借 Windows 构建不可行)。改为**组装**而不是编译(见 [ADR-0009](./adr/0009-portable-package-assembled-on-linux.md)):

```
workutil/
├── workutil.bat            ← Windows 启动脚本
├── workutil.command        ← macOS 启动脚本(0o755)
├── python/                 ← python-build-standalone 解开的运行时
├── site-packages/          ← 目标平台预编译 wheels 解开的依赖
├── app/                    ← 后端源码(migrations 在包内,随目录拷贝)
├── ui/                     ← 前端构建静态产物(frontend/dist 内容)
├── pyproject.toml          ← 只为让 get_version() 找到版本号,见下
└── README.txt              ← 快速使用说明
```

所有第三方依赖(Pillow、pydantic-core、watchfiles 等)均有目标平台的预编译 wheel,组装只是将 wheel 与 Python standalone 运行时解压到对应目录,全程在 Linux 开发机上完成(`make package`)。

#### `frontend_dist` 三级查找

便携包运行时后端脱离了 git 仓库源码树。`app/core/config.py` 中的前端静态文件路径按三级顺序查找:
1. `WORKUTIL_UI_DIR` 环境变量
2. 包布局:`app/` 源码同级的 `ui/` 目录
3. 仓库布局:`<repo>/frontend/dist`

若均不存在返回非空 Path 但不中断启动,访问静态资源时友好提示 404。

#### 平台层第三个动词:`open_app_window`

独立窗口通过浏览器 app 模式实现,不做原生桌面框架(见 [ADR-0010](./adr/0010-the-app-window-is-still-a-browser.md))。`app/core/platform.py` 补充第三个动词:

- `open_app_window(url, data_dir=None)`:
  - Windows: 依次尝试 `msedge --app=<url>` → `chrome --app=<url>` → `start <url>`
  - macOS: 依次尝试 `open -na "Google Chrome" --args --app=<url>` → Edge 同理 → `open <url>`
  - Linux: 抛出 `UnsupportedPlatformError`

开窗使用数据目录下独立的 `browser-profile/` 作为 `--user-data-dir`,与日常浏览器的插件、策略及清理缓存操作完全隔离,保证 `localStorage` 的展开状态与语言偏好不受污染。

#### 端口占用与防重复启动

启动脚本设定 `WORKUTIL_OPEN_WINDOW=1`,uvicorn lifespan 启动后自动开窗。若 8765 端口已被占用,后端检测到后不会崩溃报错,而是打印提示「workutil 已经在运行」、唤起已有实例开窗并将进程以退出码 0 正常退出。

#### favicon、Web Manifest 与版本号显示

- 前端在 `frontend/public/` 提供 `favicon.svg`、`favicon.ico` 以及 192/512 尺寸的 PNG 图标,并配置 `manifest.webmanifest`(独立显示模式 `standalone`,主题色 `#4f679c`)。
- 在 Edge / Chrome 中支持「安装此站点为应用」并可在 `edge://apps` 勾选开机自动启动。
- 后端暴露 `GET /api/version` 返回 `pyproject.toml` 的版本号,顶部导航栏展示小字版本号,便于手动下载更新时核对版本。**`get_version()` 的查找路径假定 `app/` 同级有一份 `pyproject.toml`**(见 `core/version.py` 的两个候选路径);组装脚本因此把 `backend/pyproject.toml` 原样拷进包根目录。这份文件不是给运行时依赖解析用的(依赖已经解到 `site-packages/` 里),纯粹是为了让这一行代码有东西可读——曾经漏拷过一次:`app/` 是源码直接拷贝而不是 `pip install`,site-packages 里没有 workutil 自己的 dist-info,于是两条候选路径都找不到、`importlib.metadata` 也找不到,一路落回函数末尾硬编码的 `"0.1.0"`。这在无桌面开发机上验不出来(§7 的「落差」),又恰好 v0.1.0 那次真实版本号就是 "0.1.0",于是这个 bug 在整个上一个版本周期里都不可见,直到 v0.2.0 发布后才在工作机上现形。现在 `scripts/build_packages.py` 的 `verify_packages()` 和 `backend/tests/test_packaging.py` 都会解开 zip 里的 `pyproject.toml` 核对版本号,不能再悄悄漏掉。


## 4. 项目结构

新增一个功能 = 加一个目录 + 一行注册。

```
backend/app/
  core/            config.py(数据目录与监听地址)  db.py  deps.py
                   images.py —— 图片的解码、落盘、计数、清理、回传。Memo 与 Evidence 共用
                   platform.py —— open / reveal 的平台实现,经 deps 注入(§3.3)
  migrations/      Alembic;版本文件在 versions/,随服务启动自动执行
  modules/
    registry.py    功能清单 —— 新增一个功能在这里加一行
    memo/          router.py  models.py  service.py  schemas.py
    todo/
    bookmark/
    script/
    evidence/
    transfer/      数据导出与导入(§6 F7)。没有 models.py —— 它不拥有任何表,读写的是整个数据目录
  main.py          create_app():迁移、挂载各模块 router、托管前端产物
frontend/src/
  App.tsx          路由表;`/` 直接就是 Memo,不经跳转
                   `/memo/:id` 是单条 Memo 的永久链接(§6 F1)
                   `/settings` 数据导出与导入(§6 F7)
  AppNav.tsx       顶部导航
  features/
    memo/  todo/  bookmark/  script/  evidence/  settings/
  shared/          通用组件、API client、图片粘贴 hook、Markdown 渲染(Memo 与 Todo 共用,§6 F2)
                   i18n(t() / 语言包,§6 F6)
```

每个后端模块四个文件职责固定:`router.py` 只管 HTTP、`service.py` 放业务逻辑、`models.py` 是 ORM 模型、`schemas.py` 是出入参。业务逻辑不依赖 FastAPI,便于单测。`transfer/` 是唯一没有 `models.py` 的模块 —— 它不拥有任何表,操作对象是整个数据目录。

### 测试接缝

TDD 只打在事先约定的接缝上,不追求覆盖率。

**主接缝是 HTTP API**:用测试客户端驱动真实应用,配合临时数据目录。只测外部可观察的行为 —— 重构模块内部而不改变对外契约时,测试不应该失败。

| 位置 | 测? | 理由 |
| --- | --- | --- |
| HTTP API | ✅ **主接缝** | 一个接缝覆盖增删改查、搜索、图片的落盘与级联清理。临时数据目录使其与真实数据隔离 |
| 搜索:片段提取纯函数 | ✅ **重点** | 唯一低于主接缝的测试点。它无 I/O,而边界矩阵很大(中日文按字符截断、英文按词截断、多处命中、命中在首尾),走 HTTP 会冗长难读。中日文最容易错,且**英文用例发现不了**(见 ADR-0002 的教训) |
| `service.py` / `router.py` 单独测试 | ❌ | 已被主接缝覆盖;router 太薄,只做转发。直接访问 DB 仅用于安排 API 表达不了的前置状态(如「这条是 2020 年写的」),断言仍走 API |
| 前端 UI | ❌ 第一版 | 此阶段 UI 快速变形,测试会比被测代码更早过期。代价是回归靠手动 —— 可接受,因为页面少且每天在用 |

## 5. 数据设计

- **位置**:由 `platformdirs` 决定 —— Windows `%LOCALAPPDATA%\workutil`,macOS `~/Library/Application Support/workutil`
- **结构**:`workutil.db`(SQLite)+ `images/<memo_id>/`(Memo)+ `images/evidence/<evidence_id>/`(Evidence)—— 图片按所属对象分目录。Memo 的目录名永远是十进制整数,不会和字面量 `evidence` 相撞,所以 Evidence 挤进同一个父目录不需要搬迁既有数据。代价是目录树不对称,等第三个要存图的模块出现时再统一
- **不做跨机同步**(见需求文档 §3),因此不需要处理冲突合并,也不需要全局唯一 ID
- **图片**:存为磁盘文件,原图不压缩,DB 不记绝对路径 —— 目录由所属对象的 id 推出来,行里只留文件名(Evidence 的 `image_name`)或指回本服务的相对 URL(Memo 的正文)。都是为了整个数据目录可以直接打包备份、迁移
- **图片的删除跟随所属对象**:删除一条 memo 就是删掉它的整个图片目录。**Memo 不做引用计数** —— 引用计数要解析 Markdown 正文,而剪切一段文字的中间态引用数为 0,会导致不可逆的误删;留下几个无人引用的文件则是可逆且无害的
- **Evidence 是这条规则的例外,而且是有理由的例外**:它的图片引用是**结构化的**(一个 image Block 就是一张图),不是从正文里解析出来的,没有「剪到一半」的中间态。删一个 image Block 就是明确地说这张不要了。所以 Evidence 删 Block 即删文件、删 Case 即删其名下图片、删 Evidence 即删整个目录。沿用 memo 那条「**删不掉文件不算失败**」:Windows 上被看图软件占着的截图删不掉,而 DB 行已经没了,这时回错误等于撒谎

## 6. 各功能实现要点

### F1 Memo

- **图片粘贴走浏览器的 `paste` 事件**拿到 Blob 后上传,而不是后端读系统剪贴板。这样跨平台一致、无需额外依赖,且不受「服务跑在哪台机器」影响
- 检索用 **`LIKE '%q%'` 子串匹配,不用 FTS5** —— FTS5 的两种分词器对中日文都失效,实测详见 [ADR-0002](./adr/0002-substring-search-not-fts5.md)。第一版不做标签
- 搜索结果返回「正文首行 + 命中片段」。片段提取需注意**中日文按字符截断、英文按词截断行为不同**,是重点测试对象。片段最多返回 5 段,但**同时返回命中总数** —— 只看到前几处就下判断,正是「这条是不是我要找的」会判错的地方
- 正文 Markdown,存原文,前端渲染。**禁用 raw HTML** —— memo 内容大量来自外部粘贴,而页面脚本可直接调用 `127.0.0.1` 上具备任意代码执行能力的后端(F3 书签可指向可执行文件,见 [ADR-0005](./adr/0005-bookmarks-are-a-second-code-execution-path.md)),这条链必须切断
- 上面那条是**唯一有前端自动化测试的地方**(`MemoMarkdown.test.tsx`),刻意破了「前端不写自动化测试」的例:给 react-markdown 加一个 `rehype-raw` 就能悄无声息地接通这条链,而它是一行改动
- 无标题字段;列表按 `created_at` 倒序(`updated_at` 存但不参与排序,避免修改旧 memo 时把它顶到列表最上面)
- **置顶存成 `pinned_at`(可空时间戳),不是 `order` 列**。非空即置顶,值同时就是置顶区内的顺序(最近钉的在最上)。memo 之间没有先后关系,给它加 `core/ordering.py` 那套 `Ordered` 等于承认有,见 [ADR-0008](./adr/0008-memo-can-be-pinned-but-not-categorised.md)
- **置顶集合是一次单独查询,不能混进那 200 条里排序**。列表接口只取最近 `RECENT_MEMO_LIMIT` 条,一条钉住的旧 memo 会落在那之后 —— 而「钉住一条三个月前的」正是这个功能的主要用法。两个集合拼接时要**排除重复**,否则刚写又被钉的那条会出现两次
- **置顶只作用于默认列表,搜索路径完全不动**。置顶开关走 `POST`/`DELETE /api/memos/{id}/pin` 两个幂等端点而不是一个 toggle,并且**不动 `updated_at`** —— 改置顶不是修改内容,否则「修改于」会为一次点击而出现
- 列表页**不加载图片原图**,只标记「含 N 张图」,展开某条时才加载
- **展开后的图片是高度上限 200px 的缩略图,点击开灯箱看原图**。这是 §3.4 固定外壳的配套:外壳固定不了单条内容的高度,而一张 1920 宽的截图在 768px 容器里能占几百像素高,「有图 = 高度不可预测」正是布局跳动的最后一个来源。灯箱自建、不引依赖;`Esc` 要挂 document 级监听,不能照抄 `ConvertToTodoModal` 挂在遮罩 div 上的写法(那里能work是因为焦点在模态内的 input 上,灯箱里没有可聚焦元素)
- **「含 N 张图」是数目录里的文件数出来的,不存字段** —— 文件是唯一真相,不会有计数与磁盘对不上的一天。代价是目录必须干净,由两条纪律保证:①**创建 memo 时先清掉同 id 的残留目录** —— SQLite 会把回滚或删除掉的 memo 的 id 再发一次,而一条刚创建的 memo 不可能已经有图,那个目录必定是别人的;②**保存图片前先把所有图片解码完**,一张坏图让整次保存失败,不留下半套截图。200 条带图目录的列表请求实测 10ms,不值得为此加缓存
- **删除 memo 时删不掉图片文件不算失败** —— Windows 上截图被看图软件占着就删不掉,但 memo 那一行已经没了,回一个错误等于撒谎。残留目录由上面第 ① 条在 id 复用时收走
- **截图不接受 `.svg`** —— SVG 是可执行脚本的文档,而图片由本服务同源提供,正文里一个相对链接点开就是一个能调本机后端的页面,绕过 Markdown 渲染那道闸。落盘时非白名单扩展名一律记为 `.png`(字节不动),并对图片响应加 `X-Content-Type-Options: nosniff`
- **搜索与列表共用同一个上限**(`RECENT_MEMO_LIMIT`),搜索不会比翻列表返回更多行
- **界面是单页**:顶部常驻输入框(打开即自动聚焦,`Ctrl+Enter` 保存),下方是时间倒序列表;点某条**就地展开**,不跳转页面。目标是让「打开 → 输入 → 保存」这条路径上的导航点击数为零
- 展开后是渲染态,**编辑由一个「编辑」按钮进入,而不是点正文**。曾经做成点正文即进编辑,实际使用一天就退了回来:从 memo 里复制报错堆栈是每天都在做的动作,而拖选文字的按下-拖动-松开会被当成一次点击,选区当场消失。「不设查看态」要的是**不跳页**,不是不设按钮 —— 展开和编辑始终在同一张卡片里,导航点击数仍然是零
- 折叠态**也有一个编辑按钮**,点它 = 展开 + 直接进编辑态,保存后**留在展开态**(自动折叠会让人看不到自己刚存了什么)。它和上面那条不矛盾:进编辑的仍然是按钮,不是文字
- **点卡片空白处开合**,是展开箭头之外的一条补充路径。判定必须同时满足两个条件,少一个就会第三次踩进上面那个坑:①点击目标属于一张**白名单容器**(卡片本体、折叠行的 flex 容器、头部行、正文外层 div);②`window.getSelection().isCollapsed` —— 这一下没有留下选区。**编辑态不响应**(点空白就把草稿卷起来是拿数据换一次点击),`SingleMemoPage` 不参与(它没有折叠态)
- 上面那条白名单是刻意的,不是偷懒:渲染出来的正文是一串块级 `<p>`,**一段短句子右边那片看起来是空白的地方,DOM 上仍然是那个 `<p>`**。把 `<p>` 也算进空白,单击一个词就会折叠 —— 而双击选词的第一下就是单击。代价是「段落右侧点不动」,接受;`caretRangeFromPoint` 一类的启发式不用,`.scratch/memo/issues/08` 立过「不新发明一套启发式判断」的规矩
- **`Tab` 在正文里打出一个真的 `\t`**(替换选区),不做多行缩进、不做 `Shift+Tab` 反缩进 —— memo 不是代码编辑器。插入走 `document.execCommand("insertText", false, "\t")` 而不是 `setState`:后者会**清空浏览器原生的撤销栈**,`Ctrl+Z` 从此在这个框里失效,而 memo 输入框是全项目打字最多的地方。`execCommand` 已被标记 deprecated 但仍是保住撤销栈的唯一办法,返回 `false` 时退回 `setState`
- `Tab` 被吃掉之后键盘要有出口:编辑态维持 `Esc`(退出编辑、保留草稿)的既有语义,composer 里 `Esc` = `blur()`、**不清空内容**,之后 `Tab` 恢复正常移焦
- **`Tab` 只作用于 memo 的两个输入框**,evidence 的 `BlockTextArea` 明确不动 —— 制表符是它判断「这段粘贴是不是表格」的判据(见 §6 F5),手打的 Tab 会污染那道粗筛
- `/memo/:id` 是单条 memo 的永久链接。它**不改** `/` 的形状 —— 上面那条「单页、零导航点击」说的是「打开工具到写下东西」这条路径。它原本是 Todo 回溯链接的目标;那条链接随 memo→Todo 转换一起作废后(见 §6 F2),它的入口改由迁移写进 Todo 说明里的 Markdown 链接提供
- 编辑区是纯 Markdown 文本框,**不做所见即所得** —— 富文本编辑器的粘贴与光标处理成本高,而这里要的是低摩擦而非排版能力

### F2 Todo

- 排序是**手工的**(`order`,上下移动 + 置顶置底,复用 evidence 的 `_reordered` / `Move`)。`due_date` 可选、**不参与排序**,只负责显示 —— 大多数待办没有 deadline,拿它当排序键的结果是绝大多数项挤在「没有日期」的一坨里,而优先级只有人知道
- `due_date` 只到**日**,不带时分:自用待办的粒度从来不是小时,带上时间就要处理时区和「几点算逾期」。显示分三档:**逾期红 / 今天橙 / 其余灰**。**不做提醒通知** —— 那需要一个常驻进程,超出本工具的形态
- 完成即从主列表移出,进一个**默认折叠的「已完成」区**,可展开、可撤销。存 `completed_at`,**不自动清理**(本地自用,一年也攒不到会拖慢查询的量,而「上周做完了什么」是白捡的)
- **完成时 `order` 原样不动**,撤销就回到原来的位置。若改成置底,一次误点就永久打乱了手工排的优先级 —— 那正是上一条花力气保住的东西
- **未完成项全量返回、不设上限**(看不见的待办等于不存在);已完成区按 `completed_at` 倒序并设上限,沿用 `RECENT_*_LIMIT` 的做法。已完成区是唯一会无限增长、也是唯一不需要看全的地方
- 完成 / 撤销是**两个独立动词**(`POST {id}/complete`、`POST {id}/reopen`),不是 `PATCH {done: true}` —— 和 evidence 已经定型的写法一致(状态转移是动词,字段编辑才是 PATCH),而且 `complete` 要顺带写 `completed_at`,藏进通用 PATCH 里迟早有人改了 `done` 忘了时间戳

**说明(description)**:

- `todos.description` 是 todos 表上一个普通的 `Text` 列(default `""`),**不是外键、不是关联表**。它和 Memo 正文形态相同、概念不同 —— 生命周期是那条线,见 [ADR-0012](./adr/0012-a-todo-description-is-not-a-memo.md)
- `TodoUpdate.description: str | None` —— `None` = 不改,`""` = 清空。**不用** `due_date` 那套 `model_fields_set` + `update_due_date` 的 sentinel:`due_date` 需要它是因为 `null` 本身就是一个合法的目标值,而空字符串和「没传」在这里天然可分
- `GET /api/todos` **带说明全文回来**。对照组是 evidence 的 Block(按 Case 单独读,因为一个 Case 可能挂着一整天的截图)—— 说明是纯文本、没有图片,体积有上界,带回来换到的是「展开即刻可见」
- 说明**不参与搜索、不能置顶、没有自己的时间戳**。哪天它真的需要被独立搜索,那说明它其实是一条 Memo,该重开 ADR-0012 而不是给 Todo 加搜索
- 说明**不支持图片**。图片链路是共享的、复用成本不高,但一旦说明能装截图,它和 Memo 就只剩「有没有勾选框」这一个区别
- 渲染复用 **`shared/Markdown.tsx`** —— 从 `features/memo/` 提上来的,连同那条「禁用 raw HTML」的安全线与它的守卫测试。**`features/todo` 不许依赖 `features/memo`**(旧的正向依赖随转换一起拆掉了,不该在拆的同时留下反向的新债)
- 前端:**有说明才显示展开箭头**(没说明的是多数,一列灰箭头全是噪音);展开状态按 id 持久化到 localStorage,照抄 `MemoList` 的写法;已完成的 Todo **可展开、只读**(和「已完成不能编辑」一致);说明在**现有的编辑表单**里改(标题 + 截止日期 + 说明一次保存),不另开一个编辑态

**memo 转出已作废**。曾经有一条 `source_memo_id`(只存 id、不建 FK)和 memo 卡片上的「转 Todo」按钮,requirements.md §4 F2 把它写成「与 F1 打通」。Todo 长出自己的说明之后它的存在理由就消失了 —— 当初要带过去的本来就是那段描述,而不是那条 memo。拆除时:

- drop `todos.source_memo_id`,但**迁移里先把还活着的链接接住** —— 凡该列非空且那条 memo 仍在的,往新的 `description` 里追加一行 `[原 memo](/memo/N)`。线索留在说明里,而不是随列一起消失
- 这条迁移顺带把 `/memo/:id` 的 UI 入口还了回来(徽章链接拆掉之后它一度只能手敲 URL),所以那条路由**保留**
- `ConvertToTodoModal.tsx`、`TodoItem` 的徽章、`router.py` 里那套 `get_existing_memo_ids` 过滤一起删。`firstLine.ts` **不删** —— 折叠态 memo 的首行还在用它

### F3 书签

**模型是两层**:Group(一批要一起打开的书签)→ Bookmark(一个指向本机文件或文件夹的入口)。一个 Bookmark 属于**零或一个** Group,同一个路径可以登记多条 —— 那不是重复,**不要给 `path` 加 `UNIQUE`**(见 [ADR-0006](./adr/0006-a-bookmark-is-an-entry-not-a-file.md))。Group 自己也有 `order`。

- **路径靠手工粘贴,不做文件选择器 —— 因为做不出来。** 浏览器不把绝对路径交给页面:`<input type="file">` 拿到的 `File` 没有 `path`,拖拽也没有(那是 Electron 才有的)。Windows 上 `Shift+右键 → 复制为路径`、macOS 上 `Cmd+Opt+C` 都是一步,而这个痛点的形状是**录入低频、打开高频**,摩擦该压在打开侧。后端目录浏览器进了 backlog(requirements.md §7):它等于给这个服务加一个「列出本机任意目录」的能力,而开发时列的还是 Linux 服务器的目录树,真实体验在服务器上验不了
- **登记时校验路径存在,不存在就硬拒绝**,话术直说「这个路径现在不存在」。「粘错了」的概率远高于「登记一个当前没插的 U 盘」,而后者的补救是把盘接上再登记一次;前者会静静躺成一条永远打不开的灰书签。不做「仍然登记」的二次确认 —— 一个平时用不到的确认按钮只会训练人闭着眼睛点它
- `name` **必填,由文件名预填**。可空就得在显示时 fallback 到文件名,UI 白白多一种状态。`path` 事后可改(文件搬了家,改路径比删了重建自然),走同一道校验。不加备注字段,`name` 就是备注
- **书签也能指向文件夹**(requirements.md §4 F3)。文件夹和文件在两个平台上是同一个调用,零额外成本,而「打开项目目录」是真实高频。文件夹书签**不显示**「打开所在文件夹」(没人想要父目录),后端 `reveal` 对它回 422 —— 这道门不能只靠前端不画
- **一键打开整组**:按 `order` **串行**、每个之间 200ms,**同步等完再返回一份汇总**(`opened` / `skipped` 各是哪些、为什么)。失效那条**跳过、其余照开**,不整组失败 —— 和 memo「删不掉文件不算失败」是同一条纪律:按下这个按钮要的是那 6 个文件被打开,不是一份完美的事务。汇总必须回来,否则「跳过了 2 个」就静默了,而 requirements 明确要求失效不能静默失败。10 个文件 = 2 秒,后台化要引入状态查询接口和一份进度状态,不值。不设条数上限(组是自己一条条攒的)
- **失效检测是一个单独的接口**(`POST /api/bookmarks/check`),不在列表接口里做。本文档此前那句「列表加载时批量 `os.path.exists`,不阻塞渲染」是自相矛盾的:在列表接口里做它就**是**阻塞的,而 Windows 上一条指向已断开网络驱动器的路径能卡好几秒,整个列表跟着卡。列表先渲染,检查结果回来再打灰标;**结果回来之前显示「未知」而不是「有效」**,不给没验证过的东西盖绿章
- 删掉一个 Group,成员**变成散装书签、不跟着删**(ADR-0006)
- **改归属靠拖拽,一次原子请求**。整个书签页共享一个 `DndContext`,书签可以在「散装 ↔ 任意分组 ↔ 另一个分组」之间任意方向拖,落在松手的位置;组之间的排序拖拽照旧,靠 dnd-kit 的 `data.type` 把两类可拖动的东西分开。后端是**一个**端点同时改 `group_id` 和两侧序号(走完还要给**原组**的兄弟收拢序号,`Ordered` 要求连续)—— 拆成「先 PATCH 归属再 move」会留下「落在末尾而不是松手位置」的中间态。请求 schema 定义在 bookmark 模块里,**不要给共享的 `core/ordering.py` 的 `MoveRequest` 加 `group_id`**,那会让 todo 和 evidence 也长出一个它们没有的概念。空组要能接住:组容器本身注册成 droppable,拖拽中显示虚线占位区。编辑表单里的分组下拉框保留(键盘操作、以及组太多拖很远的场景)
- **能打开的东西就能执行**:一个指向 `.bat` / `.exe` 的书签点一下就是执行,这是本工具第二条任意代码执行链,知情接受,不加扩展名黑名单(见 [ADR-0005](./adr/0005-bookmarks-are-a-second-code-execution-path.md))

### F5 Evidence

**模型是三层**:Evidence(一个 xlsx 文件)→ Case(一个测试用例,导出后是一个 sheet)→ Block(用例里的一段内容,在 Case 内有序)。只看 requirements.md 容易以为是两层,不是 —— 理由见 [ADR-0003](./adr/0003-evidence-is-a-workbook.md)。

- Block 有 `kind`:`text` / `image` / `table`。Log 归进 `text`,不单列一类
- Block 有可选的 `label` 当小标题(「事前準備の DB データ」)。**没有步骤编号**
- 一个 image Block 装一张图。一次粘 3 张 = 3 个 Block,各自可加 label、可单独排序。前端按粘贴顺序**逐个 POST**,而不是一次发一批 —— 一个 Block 一个请求,落地顺序就是粘贴顺序,中途失败也只是少了后面几张,前面几张已经在服务器上,不必回滚
- Case 与 Block 的顺序靠 `order` 字段;交互是**拖拽把手排序 + 保留置顶 / 置底按钮**(详见 `.scratch/drag-reorder/`)。此前曾决定「不做拖拽」,理由是依赖与键盘可达性成本不值;后通过引入 `@dnd-kit/core` 与 `@dnd-kit/sortable` 自带的键盘传感器(空格拾起、方向键移动、空格放下)解决了可访问性顾虑,并配合专门的拖拽把手避免与行内控件冲突,长距离移动仍可用置顶/置底一步到位
- Block **按 Case 一次读一份**(`GET /api/evidence/<id>/cases/<id>`),不跟着 Evidence 详情一起回来 —— 屏幕上只有当前 Case,而同一份 Evidence 的其他 Case 可能挂着一整天验证的截图。切换 Case 时用**等高骨架占位**而不是一行 loading 文字(否则内容区先塌陷再撑开,§3.4),并且**不缓存**已读过的 Case:缓存会带来「别处改了、切回来看到旧的」的一致性问题
- **复制 Case 时,图片必须连文件一起复制成新名字**。Evidence 的图片引用是结构化的、不做引用计数(§5),`delete_case` 会按 `image_name` 逐个删文件 —— 副本若共享同一个 `image_name`,删掉副本就会静默删掉原用例的截图。这是这个功能唯一会造成数据损失的失败模式,自动化测试里有一条专门守着它。新用例的名字由服务端生成(`原名 (2)`,撞了继续递增,超出 31 字符上限时**截断原名**而不是拒绝复制),插在原用例紧后面,返回**整个 cases 列表**(插入会改变后面所有 `order`);前端切过去后立刻进入重命名 —— 自动生成的编号几乎一定不是记录者要的那个,而用例名就是交付出去的 sheet 名
- 文字 Block **不允许为空**(不要了就删掉它);粘贴带来的首尾空行和行尾空格去掉,但**第一行的缩进保留** —— `strip()` 只削得掉第一行的缩进,会让它下面每一行都吊在半空,而 log 就是文字 Block
- 文字 Block 带一个 **`split_lines`**(bool,default `True`):导出时这段文字是**每行各占一个 Excel 行**,还是整段挤进一个单元格。默认逐行,因为 log 就是这么读的。接口是 `PUT .../blocks/<id>/split-lines`,和 `has_header` 的 `PUT .../blocks/<id>/header` **同形** —— 它们是同一类东西(某个 kind 专属的一个布尔开关),同类东西该长一样,不塞进 `PATCH` 的正文里
- 这个开关挂在 **Block 上而不是导出时**,因为它描述的是**内容是什么**(这段是逐行的日志 / 这段是一句说明),不是导出时的心情。一份 evidence 里两种文字同时存在是常态,挂在导出上会强迫它们同命。工具条上的开关**只在该 Block 含 `\n` 时显示** —— 不含换行时它没有任何含义
- 小标题是**独立接口**(`PUT .../blocks/<id>/label`):它属于三种 kind 里的每一种,而正文只属于其中一种
- 加 Block **只有一个入口**(`POST .../blocks`),请求体按 `kind` 做 discriminated union,各带各的 payload。没实现的 kind 不在 union 里,于是「声称是图片却没有图片」在进业务逻辑之前就被挡掉;同理 `PATCH .../blocks/<id>` 只改文字 Block 的正文,对图片 Block 是 422 而不是悄悄写进一个用不到的列
- **加完 Block 之后滚到它那里**(`scrollIntoView({ block: "nearest" })`,三种 kind 都滚,一次粘多张图滚到最后一张)。新 Block 追加在列表末尾,而人常常正停在中间 —— 加完屏幕上什么都没变,分不清是成了还是没成。**刻意不加 toast**:病根是「看不见」,不是「没被告知」,而滚过去同时回答了「成了吗」和「在哪」。表格那条既有的「识别为表格 · 改为纯文字」提示不动,它本来就兼着这个职责。不用 `smooth` —— 连着粘几张图时动画会互相打断,在 §3.4 的滚动容器里看起来像卡顿

**图片链路与 Memo 共享,代码已下沉**:解码、落盘、计数、清理原本长在 `modules/memo/service.py` 里,M2 第一步把它们提到了 `core/images.py`(`save` / `save_and_link` / `count` / `discard` / `discard_file` / `serve`),按「目录 + URL 前缀」参数化。这是 ADR-0001 那句「共享机制、不共享概念」的具体落点 —— 共享的是这条链路,**不是**一个「有图片的东西」的公共基类。「哪个目录属于谁」留在各自的模块里(memo 的在 `memo/service.py` 的 `memo_images_dir`,evidence 的在 `evidence/service.py` 的 `evidence_images_dir`)。

图片响应那条安全线(路径穿越防护 + `X-Content-Type-Options: nosniff`)也收在 `core/images.py` 的 `serve` 里,两个模块的图片路由都只是转发 —— 这条线两边必须一样,而抄一遍就意味着有一天只改一边。

**image Block 存的是 `image_name`,一个文件名而不是路径** —— 目录由 `evidence_id` 推出来,所以整个数据目录仍然可以整体搬走(§5),一行也没法指到别的 Evidence 的文件上。**同一份 Evidence 的所有 Case 共用一个图片目录**,所以删 Case 是按名字逐个删文件,而不是删目录 —— 删目录会把同门其他 Case 的截图一起带走。删 Evidence 才是删整个目录。

#### 表格

- 来源是 DB 客户端复制出来的结果集。实测 IDEA 自带的 database 工具**只往剪贴板放 `text/plain`**,格式由结果集右上角的 data extractor 决定(DSV 家族默认 TSV);`text/html` 只在从网页或 Excel 复制时才有。所以 **TSV 是主路径,`text/html` 是兼容**
- **解析放后端**:前端把剪贴板文本原样 POST,拿回 `rows` 与行列数。它是本模块边界矩阵最大的纯函数(引号、含制表符或换行的单元格、CRLF、各行列数不齐、结尾空行),放后端就落进既有的 HTTP 主接缝,不必为它破「前端不写自动化测试」;服务在 `127.0.0.1`,一次往返可忽略
- 存 `rows: string[][]` 加 `has_header`,粘贴时解析定型。不存原始 TSV 事后再切 —— DB 的文本字段本身就可能含制表符,粘贴那一刻是唯一还知道单元格边界的时候
- **`has_header` 不能靠猜**:IDEA 复制时带不带表头,取决于 Settings → Tools → CSV Formats → TSV 里的「First row is header」,工具这边无从判断。默认 `true`,UI 上一键可翻转
- 贴进来之后能删行、删列、改单元格。**刻意不给加行加列** —— 数据来自 DB,能手工加行就意味着 evidence 里可以出现编造的数据。落到接口上就是 `PUT .../cells/<row>/<column>`、`DELETE .../rows/<row>`、`DELETE .../columns/<column>` 三个门,**没有对应的 POST**;删到只剩一行或一列时拒绝,和文字 Block「不允许为空,不要了就删掉它」同一条规矩
- TSV 用标准库的 `csv` 读,不用 `split("\t")` —— 引号正是让单元格能装下制表符和换行的东西,而那些恰恰是拆错了会让后面每一格都错位的值。行尾统一到 `\n`,首尾的空行丢掉(空*单元格*的行不丢,那是 NULL)

**粘贴时怎么决定生成哪种 Block**:先看有没有表格(`text/plain` 里有制表符且多行,或 `text/html` 里有 `<table>`),有就走 table 这条路;否则有图片 flavor → image;都不是 → text。**先问表格再问图片,顺序是刻意的**:从 Excel 复制一段区域,剪贴板上同时有 TSV、`<table>` 标记和一张单元格的 PNG —— 先问图片就会把一张表变成一张截图,而那正是表格这种 kind 存在的意义所要防的(requirements.md §4 F5)。「有图片 flavor」只有在旁边没有更好的东西时才意味着「这是一张图」。反过来不会误伤:截图既没有制表符也没有 `<table>`,从网页上复制的图片也一样(它的文本是 URL、标记是 `<img>`)。这个判别一定会误判(带缩进或对齐的日志长得像表格),所以生成后挂一条**可无视的确认提示**(「识别为表格,8 行 5 列 · 改为纯文字」)。判对时零成本,判错时一次点击,而这条提示同时也是「刚才那一下确实进去了」的反馈。

判别由谁做,决定了接口长什么样:

- 加 Block 那一个入口的 union 里多一个 `kind: "paste"`,**它不是第三种 kind,而是「没有 kind」**。前端把 `text` 与(有的话)`html` 原样送上来,回来的 Block 上的 `kind` 才是答案。union 里**没有** `table` 成员:表格不是被要求出来的,是被认出来的,唯一的来源就是一次被读成了查询结果的粘贴
- 前端只做一道**必要条件**的粗筛(有制表符且多行,或 `text/html` 里有 `<table>`):过不了的粘贴根本没有表格可切,就照常落进输入框等 Ctrl+Enter。这道筛子省下的是每一次普通粘贴的往返,以及「随手粘句话就变成一个 Block」的意外;真正的判别仍然只在后端做一次
- 表格 Block 另存一份**原始粘贴文本**(`table_source`)。「改为纯文字」要交回一字不差的原文,而从 rows 拼回去做不到 —— 去引号不是可逆操作。它只为这一件事存在,永远不会被事后重新切一遍;Block 还是同一个 Block,label 和位置都不动。这一条是 [ADR-0004](./adr/0004-table-is-a-first-class-block.md)「不存原始 TSV 事后再切」的细化而非例外,已记在该 ADR 里
- **由此带来一处不对称,是知情的**:粗筛放行的粘贴当场就成为一个 Block(哪怕后端最后判成 text),粗筛拦下的则照常落进输入框等 Ctrl+Enter。所以「用制表符缩进的日志」会立刻变成一段 text Block,而「用空格缩进的同一段日志」要按一下 Ctrl+Enter。代价是这点不一致,换来的是普通粘贴不必每次都往返一趟;两条路都不丢内容
- **「改为纯文字」不只挂在那条确认提示上**:提示是会过期的(只在本次打开这个 Case 期间显示),而表格 Block 的工具条上常驻一个同样的入口。误判往往是导出前通读时才发现的,那时提示早已不在 —— 一条会过期的提示可以是提醒,不能是唯一的门

#### Excel 导出

本功能最琐碎的一块,也是唯一被文件格式硬限制卡住的地方。

**样式的基准是「从 a5m2 粘进 Excel 的样子」,不是「工具自己定」** —— 既存的 evidence 全是那么手工做出来的,工具生成的那几份要能和它们并排交付。requirements.md §3 那句「自由格式」已随之改写,理由见 [ADR-0011](./adr/0011-excel-style-follows-a5m2.md)。落到具体四项:

- **字体 `游ゴシック` 11**(此前是 openpyxl 默认的 Calibri,和既存 evidence 不一样)。xlsx 里字体按名字存,渲染取决于打开它的机器:日文 Windows 一定有,macOS 装的是 `YuGothic` / `游ゴシック体`、名字对不上时 Excel 自己回退 —— 在 Mac 上预览和工作机不一样是已知且接受的偏差,交付对象在工作机那边
- **表头 `wrap_text` + 垂直居中,数据行不设 alignment**(长值被右邻格截断、不折行)。表头换行不只是「像」:`loop_kaiin_id` 在 18 宽的列里会被截断,而列名是交付内容
- **值恰为 `≪ NULL ≫` 的单元格字体色 `#808080`**。精确匹配那一个字符串(U+226A + 空格 + `NULL` + 空格 + U+226B),不 trim、不认变体、不用正则 —— 数据里真实存在一个长得像 NULL 的字符串是可能的,而 evidence 的底线是「我看到的就是这个值」,**宁可漏判不可错判**。只作用于表格单元格,文字 Block 不参与;判定在导出时按值做,不在粘贴时打标记(单元格可能被 `PUT .../cells/...` 改过)
- 字体、颜色、bold 全部经由 `layout.py` 的 **`_text_cell` 这一个漏斗**设置 —— 它已经是「每一格都要经过」的地方(剥控制字符、摁住 `data_type`),字体属于同一类事。`Font(...)` 的构造也收进去,调用方只传 bold / color,免得三处各自记得带 `name`。**不改 openpyxl 的 `Normal` 命名样式**:那是半私有 API,升级会静默变

**列宽 18 是明确的例外,不向 a5m2 对齐。** a5m2 粘贴根本不设列宽 —— Excel 里看到的是它自己的默认值(8.38 字符),不是 a5m2 的选择,这一项上没有对齐的对象。18 是为「同一 sheet 里图片和表格共存」定的,窄回去受损的是截图那半边。

- 一个 Case 一个 sheet,sheet 名就是 Case 名。**合法性在录入时校验,不在导出时清洗** —— sheet 名是交付内容的一部分,导出时悄悄改名等于交给使用者一个他没检查过的文件。约束:非空、≤31 字符、不含 `: \ / ? * [ ]`、同一 Evidence 内不重名。**注意 openpyxl 只对非法字符抛 `ValueError`,超长仅发一个 `UserWarning` 并原样写入**(实测 3.1.5),长度这一关它不兜底。规则落在 `modules/evidence/service.py` 的 `validate_case_name`,建 Case 和改名都过它
- 排布是**单列纵向**:每个 Block 从 A 列起依次往下,之间空一行,label 加粗单占一行。不采用「A 列 label / B 列内容」的两列布局 —— 截图和 DB 结果的宽度差着数量级,固定列宽必然压扁其中一种
- **图片不撑行高,而是预留行**:Excel 行高上限 409 磅,96 DPI 下 1 px = 0.75 磅,即一行最多装 545 px —— 截图基本都比这高。做法是不动行高(默认 15 磅 = 20 px),按 `N = ceil(图片高px / 20)` 预留 N 行,图片浮动锚在第一行。openpyxl 的图片本就不撑开行高,不预留就会压住下方内容,而 requirements.md 验收要点里「不重叠、不溢出」防的正是这个
- 宽度靠**等比缩放到最大宽度**(默认 900 px)。缩放只作用在导出的那一份上,磁盘原图不动 —— 改了参数重导一次就是另一个尺寸,原始画质永远在
- 表格:表头行加粗 + 底色 `#87e7ad`,全表细边框。**不用 Excel Table(ListObject)** —— 它强制列名唯一,DB join 出来的两个 `id` 会被自动改成 `id` / `id2`,交付物里的列名被工具偷偷改掉不能接受;筛选器在一份给人看的证跡里也只是噪音
- **所有单元格统一写 `@` 文本格式**。`007`、`2024-01-01`、18 位 ID 交给 Excel 自动识别会分别变成 `7` / 日期序列号 / 科学计数法,而 evidence 的全部意义就是「我看到的就是这个值」。代价是 Excel 会挂「以文本形式存储的数字」绿色三角,接受它(理由见 [ADR-0004](./adr/0004-table-is-a-first-class-block.md))
- **同一个 Case 里的多个表格共用列宽** —— 一个 sheet 只有一套列宽。这是 Excel 的形状,不是实现偷懒,不要试图修
- 文字 Block 按它的 `split_lines` 走两条路:**逐行**(默认)时每行写一个单元格、占 `len(lines)` 行、**不设 `wrap_text`** —— 一行 log 就该是一行,超长时向右溢出(文字 Block 右边本来就是空列)比折成 20 行高的一格好读,而且这正好和上面「数据行不 wrap」一致;**合并**时仍是一格 + `wrap_text`,和现在一样。空行原样成为一个空 Excel 行(`"a\n\nb"` → 3 行)—— 空行是内容的一部分。Block 之间空一行的规则不变
- 排版参数(列宽、最大图片宽度、底色、边框、字体、NULL 的字面量与颜色)集中在一个 `LayoutSettings` dataclass,值写在代码里。**第一版不做配置文件** —— 「做成配置」要的是参数集中而非散落在导出代码各处;真到了要套公司模板那天,换个数据来源即可,不必重写。**但这些值从此有了外部依据**(见 ADR-0011),改之前要能说出「a5m2 粘出来就是这样」
- 文件名 `エビデンス_<title>.xlsx`,title 里的文件名非法字符(`\ / : * ? " < > |`)替换为 `_`。和 sheet 名的处理不同是有理由的:文件名不是交付内容,对方拿到就会按自己的规矩改。**它是非 ASCII,`Content-Disposition` 必须用 RFC 5987 的 `filename*=UTF-8''...` 形式**,只给 `filename=` 在部分环境会拿到乱码
- 零个 Case 的 Evidence **拒绝导出**(工作簿必须至少有一个 sheet,生成一个只有空 sheet 的文件是在交付一个错误);零个 Block 的 Case **允许**,出一个只有名字的空 sheet ——「这个用例我确认过,没有要贴的东西」是真实存在的情况

#### Evidence 列表

创建时间倒序,显示 title / Case 数 / 时间,固定上限(`RECENT_EVIDENCE_LIMIT`),与 memo 的 `RECENT_MEMO_LIMIT` 同一套做法。Case 数在列表查询里一次 join 算出,不是每行再查一遍。**不做搜索** —— ADR-0001 把「靠搜索捞回」明确划给了 Memo;真攒多了该加的是归档(把做完的挪出视线),不是在做完的里面找。

### F6 多语言

- **自研极简 i18n,不用 react-i18next**:一个 `t(key)` 函数 + React Context(当前语言、切换方法)+ 每种语言一个 JSON 语言包(`shared/i18n/zh.json`、`shared/i18n/ja.json`)。现在只有 45 个源文件、两种语言,不需要复数规则、插值、命名空间这些库要解决的问题;真到了需要那天再换库,替换面只在 `shared/i18n/` 内部
- **默认语言来自 `navigator.language` 探测**,不是显式部署配置 —— 不需要区分「这是工作机还是私人机」,浏览器语言本身就是最接近的信号。探测结果既不是 `zh` 也不是 `ja` 时兜底为 `zh`(现状全部是中文)。用户手动切换过之后,选择存 `localStorage`,覆盖探测结果 —— 每台机器 / 每个浏览器各自记忆,和「两台机器数据各自独立」的既有架构一致,不经过后端
- 切换器**留在导航栏(`AppNav.tsx`)里**。M7 起有了 `/settings`(见 §6 F7),但语言不搬进去:切语言是**当场就要看到效果**的动作,而且它是唯一一个在任何页面上都可能想改的偏好。`/settings` 装的是「一次性的、要专门去做的」事(数据导出导入),两者不是一类
- **key 缺失时渲染裸 key 本身**(如 `[todo.empty_state]`),不做静默 fallback 回中文 —— 静默 fallback 会让「日语翻译漏了」这件事在正常使用中不可见,而裸 key 是明显的、当场就能发现的信号
- **后端错误信息改用 error code**,不再直接把 Python 异常的字符串消息透传给前端。`backend/app/modules/*/service.py` 里现有的自定义异常(`EmptyTitle`、`PathDoesNotExist` 等)统一带一个 code 字段;`router.py` 把 code 放进 HTTP 响应体,前端 `shared/api.ts` 的 `refusalFrom` 从「读 `detail` 字符串直接显示」改成「读 code,查语言包翻译」。未被特意分类的异常(非预期的 500)保留一条通用的翻译过的「未知错误」文案,不逐个分配 code —— 那些是 bug,不是需要好好措辞的用户提示
- `shared/time.ts` 的 `toLocaleString` locale 参数**跟随当前语言**(`zh-CN` / `ja-JP`),只是把硬编码参数换成读 Context,不涉及翻译 key
- **测试**:一个 key 对齐测试,断言 `zh.json` 与 `ja.json` 的 key 集合完全相同 —— 这是「以后新文案必须中日一起提交」这条工作流规则的强制手段,少一个 key 就让它在通常的测试命令里失败,不依赖开发者自觉

### F7 数据导出与导入

换电脑用。数据目录本来就是备份单位(§5),难的不是备份,是**在新机器上放回去** —— 那个位置在工具第一次启动之前根本不存在。所以导出和导入是**一对**,只做一半等于没做。

- **导出前必须取一份一致的快照**,不能直接把 `workutil.db` 塞进 zip。库**没有开 WAL**(`create_engine` 不设任何 pragma,SQLite 默认是 rollback journal),拷贝撞上一个进行中的事务就会得到一个半新半旧或损坏的库 —— 而发现的时候旧电脑可能已经不在手上了。用标准库的 **`sqlite3.Connection.backup`**,几行的事
- zip 里是 `workutil.db`(快照)+ `images/` 全部 + 一份 **manifest**(workutil 版本、alembic revision、导出时间、各表条数)。manifest 是下面那条版本校验的载体,顺带让导入完能对一眼数字
- **走临时文件,不在内存里拼**。images 可能几百 MB,`BytesIO` 会直接把它顶进内存;写临时文件再 `FileResponse`,响应完删掉
- **导入只允许在工具是空的时候执行**,非空就拒绝。合并要处理 id 冲突、图片重名、两边都改过同一条 —— 而 §3 说的就是两台机器各自独立,没有合并的场景(requirements.md §7 已把「两台机器之间的数据合并」明确列为不做)
- **「空」的判据是「所有业务表都没有行」且「images 目录没有文件」,不是「db 文件不存在」** —— 启动时 alembic 已经把表建好了,那个文件一定存在。两个都查:「库空但图片还在」是上一次导入失败留下的现场,直接往上盖会留一堆孤儿文件
- **导入前把现有 db 改名成 `workutil.db.bak-<时间戳>`**,删除留给人手动。这是整个工具里唯一会覆盖既有数据的操作,哪怕判定它是空的
- **manifest 的 alembic revision 不匹配就拒绝**。alembic 只会向前升级,把新版本导出的包塞进旧版本的工具,结果是一个打不开的库
- **导入后必须重启,而且是提示人手动重启,不自作主张** —— SQLAlchemy 的 engine 还连着被换掉的那个文件。自动重启在便携包形态下要杀掉自己再拉起来,和既有的单实例逻辑(§3.5)掺在一起只会更脆
- 入口是**新的 `/settings` 页**,导航栏右侧一个齿轮图标。不挂在语言切换旁边:以后一定还会有别的设置,而「新增一个功能不应改动既有功能」是第一约束,一个页面比一个下拉菜单经得起加东西
- **跨系统迁移(Windows → macOS)书签会全部失效**,因为存的是绝对路径。这是 Bookmark 本来的样子([ADR-0006](./adr/0006-a-bookmark-is-an-entry-not-a-file.md)),不是导入的 bug;memo / todo / evidence 不受影响。写进 running.md,不在代码里做任何补救

#### 测试接缝

| 位置 | 测? | 理由 |
| --- | --- | --- |
| HTTP API:导出 → 导入往返 | ✅ **主接缝** | 造一份有 memo / todo / 书签 / evidence + 图片的数据,导出,清空,导入,逐项断言回来了 |
| 导入的三道拒绝 | ✅ 主接缝 | 非空库拒绝、images 非空拒绝、revision 不匹配拒绝 —— 三条都是「不拒绝就会毁数据」 |

| 前端两个按钮 | ❌ | 沿用一贯做法,手动跑一遍 |

## 7. 开发方式,以及一个必须知道的落差

**开发**:服务器上跑 `uvicorn --reload`(:8765)+ `vite dev`(:5173),SSH 端口转发到 macOS,在 macOS 浏览器里开发。

**使用**:在 Windows / macOS 本机启动服务,浏览器打开 `localhost`。

> ⚠️ **落差**:开发时服务跑在 Linux 服务器上,有两个行为在服务器上无法真实验证,必须拿到 Windows / macOS 本机上测:
>
> 1. **F3 书签「用默认程序打开文件」** —— 在服务器上会去开服务器的文件,而服务器没有桌面。通过 §3.3 的平台抽象层将这部分风险圈进可替换的小范围(fake platform 自动化测试覆盖)。
> 2. **便携包本身能否跑起来、app 模式窗口长什么样** —— `make package` 组装出的便携包运行依赖宿主系统的环境分派与 Chromium 内核浏览器的 `--app` 模式。缓解手段是把逻辑尽量留在 Python 里(端口检测、退出码 0、开窗分派都有自动化测试),真机上主要验证「窗口真的正常调出且无白屏」。
>
> UI、数据存取、Excel 导出则可以在服务器上完整验证。
