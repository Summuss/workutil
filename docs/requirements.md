# workutil 需求文档

> 本文只描述**要做什么**和**为什么**。技术选型与实现方式见 [design.md](./design.md)。

## 1. 背景与目标

日常开发中有一批**高频、琐碎、但一直没有好工具承载**的动作:

- 随手记的信息散落在记事本里,越积越乱、事后找不回来
- 常用文件散落在各个位置,每次重启电脑都要在文件管理器里一个个翻出来打开
- 想跑个小脚本,却要为此打开 IDE
- 改完功能要做验证 evidence,得手工往 Excel 里贴截图

这些事单个都不大,但每天重复,累积消耗可观。

**目标**:把它们收进一个统一的本地工具,降低每次操作的摩擦。

**这不是一次性项目** —— 以后想到新功能就会往里加。因此「新增一个功能的成本」是本项目的第一约束。

## 2. 使用环境

| 场景 | 环境 | 说明 |
| --- | --- | --- |
| 开发 | 家里的 Linux 服务器(Ubuntu 24.04) | 无桌面环境,从 macOS 远程连接 |
| 运行① | 工作用 Windows 电脑 | **主力使用场景** |
| 运行② | 私人 macOS 电脑 | |

工具需要在 **Windows 和 macOS 上都能使用**。

## 3. 前提与约束

| 项目 | 结论 | 理由 |
| --- | --- | --- |
| 两台机器的数据 | **各自独立,不同步** | 工作机的 memo / evidence / 书签留在工作机不外流,出于公司信息保密考虑 |
| Evidence 的 Excel 格式 | **与 a5m2 粘贴出来的样子一致** | 没有公司模板,但有既存的 evidence —— 它们都是从 A5:SQL Mk-2 复制粘贴做出来的,工具生成的那几份要能和它们并排交付。见 [ADR-0011](./adr/0011-excel-style-follows-a5m2.md) |
| 工作机能否装软件 | **不需要装** | 实测工作机可在任意位置执行程序,而分发形态是解压即用的便携包,本来就不涉及安装 |

## 4. 功能需求

### F1. Memo(碎片信息记录)

**场景与痛点**
开发过程中经常产生一些琐碎信息需要记一下。目前记在记事本里,累积多了很难管理,想找的时候找不到。

**需求**

- 极低摩擦地录入 —— 打开就能写,写完即走
- 内容不只是文字,**有时包含图片**
- 事后能靠关键词快速找回
- 已记录的内容可以修改、可以删除
- 少数天天要看的 memo 可以**置顶**,打开就在眼前,不用翻也不用搜
- 正文里能打出**制表符** —— 贴进来的东西经常要对齐,而 `Tab` 现在会把光标弹走
- 展开和折叠不必每次都去够那个小箭头:**点卡片上的空白处**就能开合
- 折叠状态下想改一条,**一步进入编辑**,不用先展开再找编辑按钮
- 编辑到一半误按 `Esc`,**写的东西不能没**:收起编辑器,内容留着,卡片上看得出「这条还有没保存的修改」
- 那份没保存的东西**活过刷新、活过关掉浏览器**,直到保存成功或被明确放弃
- **还没保存的新 memo 也算数** —— 写到一半去看了别的页面,回来它还在输入框里

**验收要点**

- 截图复制到剪贴板后,能直接粘贴进 memo 并正确保存、正确回显
- 打开工具时光标已经在输入框里,录入一条纯文字 memo 只需「输入 → 保存」
- 关键词能匹配到正文的**任意位置**,且结果要显示命中片段,而不是只显示开头
- 置顶一条**很旧的** memo(旧到已经不在列表里)之后,它依然稳定地出现在顶部
- 一眼分得清哪些是置顶的、哪些是刚写的
- 开始搜索后,列表就是纯粹的搜索结果,置顶项不会赖在最上面挡着
- 在正文里按 `Tab` 打出一个制表符,再按 `Ctrl+Z` **能撤销掉它**
- **拖选一段报错堆栈复制出去,memo 不会因此展开或折叠** —— 这是这个功能唯一不能破的一条
- 编辑到一半点到卡片空白处,**不会**把正在写的东西卷起来
- 编辑一条 memo 写几个字,按 `Esc`,卡片标出「未保存」;**刷新页面,再点编辑,写的还在**
- 点「放弃」会先问一次,确认之后那份修改才真的没了,卡片回到已保存的样子
- 在输入框里写一半、点去待办再点回来,**写的还在**;刷新也还在
- **行为验收**:连续三天使用,期间没有再打开记事本

> Memo 没有标题字段 —— 强制起标题与「极低摩擦」直接冲突,而搜索已经实现了「以后好找」这个目的。
>
> **「不丢」这条是全工具通用的**,不只是 memo:Todo 的编辑表单、Evidence 的文字块,凡是为了改一件事而打开的一整块东西,都算一份**草稿**,`Esc` 只收起、不丢弃。只有独立的单行改名(用例编号、Block 小标题、Evidence 标题)没有草稿 —— 那是「双击、改一个词、回车」,重打的成本接近零。
>
> **置顶不是归类**:它是「这条现在常用」一个比特,没有维度、没有名字、发生在记录之后,所以不构成录入负担。归类(标签)仍然不做,见 §7 与 [ADR-0008](./adr/0008-memo-can-be-pinned-but-not-categorised.md)。
>
> Memo 的**正文不响应点击**(点空白才开合)。这是用了一天之后回退过一次的地方:从 memo 里复制文本是每天都在做的动作,而拖选的「按下 → 拖动 → 松开」会被当成一次点击。见 design.md §6 F1。
>
> 数据可以整体导出用于换电脑,见 §4 F7。

### F2. Todo List

**场景与痛点**
待办事项是日常高频需求。而一行标题经常说不清那件事到底是什么 —— 报错长什么样、要动哪个文件、上次卡在哪一步,这些以前没地方写。

**需求**

- 基础能力:新增、完成、删除、排序
- 可选:截止日期
- 每条 Todo 可以有一段**说明**,写清楚那件事是什么;列表里默认收起,**展开才显示**
- 说明里贴命令行和报错要好读 —— 和 memo 正文一样的呈现
- 编辑到一半误按 `Esc`,**标题和说明一起留着**,不会只剩半截

**验收要点**

- 已完成项不干扰未完成项的浏览
- 误点「完成」之后能撤销,并且回到原来的位置
- 一眼看得出**哪几条有说明**,没说明的不占额外的视觉位置
- 展开一条 Todo 看说明,再刷新页面,它**还是展开的**
- 已完成的 Todo 也能展开看说明(只读)
- 改着标题和说明时按 `Esc`,列表里看得出这条有没保存的修改;再打开,**两个字段都是你刚才写的那一版**

> Todo 的说明**不是一条 Memo**。形态相同(都是字、都走 Markdown),概念不同:Memo 独立存在、能搜索、能置顶;说明依附于那件待办,随它消失。见 [ADR-0012](./adr/0012-a-todo-description-is-not-a-memo.md)。
>
> 因此「memo 一键转 Todo」**已作废**。当初要带过去的本来就是那段描述,而不是那条 memo;Todo 有了说明之后,绕经 memo 这一步就没有理由了。说明**不支持图片**,截图属于 Evidence 或 Memo。

### F3. 文件书签

**场景与痛点**
常用文件散落在各个位置。**重启电脑后需要在文件管理器里一个个找出来打开,很不方便。**

**需求**

- 把文件**或文件夹**登记为书签,快速打开其中某一个
- **书签可分组,并且能一键打开一整组** —— 这才是真正解决「重启后逐个打开」的点,应作为核心能力而非附加
- 用系统默认程序打开文件
- 也能打开文件所在的文件夹
- 文件被移动或删除时,给出失效提示,而不是静默失败
- 登记时就能发现路径写错了,而不是等到某天点不开才知道
- 整理归属靠**拖动**:把书签拖进某个分组、拖到另一个分组、或拖回散装区,不用为此打开编辑表单

**验收要点**

- 在 Windows 上点击书签,文件由系统默认程序打开
- 一键打开分组后,该组内所有文件都被打开;**其中若有失效项,其余照常打开,并明确告知跳过了哪几条**
- 指向不存在文件的书签有明显的失效标识
- 登记一条路径写错的书签会被当场拒绝,而不是变成列表里一条永远打不开的项
- 把一条散装书签拖进分组,它落在松手的那个位置(组内顺序就是一键全开的打开顺序);拖错了能再拖出来

### F5. Evidence(验证証跡 → Excel)

**场景与痛点**
工作中修改完某个功能之后需要做验证,这个验证过程要整理成 evidence。目前全靠手工往 Excel 里贴截图、贴 DB 查询结果。

**evidence 文件长什么样**
一个 evidence 文件对应**一批测试用例**,每个用例占一个 sheet。sheet 名是测试用例编号,由记录者自己填,不一定是数字(`1`、`2`、`2~5`)。一个用例里通常有:事前准备的 DB 数据、画面截图、日志输出、DB 更新后的结果 —— 也就是**文字、图片、表格**三种内容,按顺序排下来,每段可以带一个小标题。

**需求**

- 方便地录入截图和文字
- **从 DB 客户端复制的查询结果能直接粘进来**,并保持行列结构,而不是变成一坨文字
- 一份 evidence 可以有多个测试用例;用例能增删、改名、调整先后
- 用例内的内容能调整顺序
- **一个用例能整个复制成新用例** —— 几个用例常常只差一两个值,截图和表格不该重取一遍
- 一键导出成**一个** Excel 文件,一个用例一个 sheet,图片嵌在里面
- 加完一段内容,**看得见它落在哪** —— 现在新内容加在列表末尾,而人常常正停在中间,加完屏幕上什么都没变
- 一段带换行的文字,导出时能选择**整段挤进一个单元格**还是**每行各占一行**,默认每行各占一行(日志就是这么读的)
- 导出的 Excel 要**和从 a5m2 粘进 Excel 的样子一致**,这样工具生成的和手工做的能并排交付
- 做 evidence 时要查 memo,能**在同一个画面里查**,不用离开当前用例
- 离开这份 evidence 再回来(刷新、切去别的功能、第二天重开),**还在你离开时的那个用例**,不是第一个
- 从导航条点 Evidence,回到的是**上次在做的那份**,不是列表 —— 列表仍然在那一页的「返回列表」上,一步可达
- 用例底下那个粘贴框里写到一半的东西,和 memo 一样**不会因为切去别的页面而没**
- 认错了的表格改成文字之后**能再改回表格**;反过来,本来就没被认出来的查询结果也能转成表格
- 截图还没写进剪贴板就按了粘贴、贴上来的其实是上一张时,**当场拦一下**,而不是等到导出前通读才发现
- 截图**能点开看原图** —— 卡片上是缩着的
- 一个用例里截图又多又长时 —— 整页长截图,或者笔记本屏幕小、普通截图也放不进一屏 —— **每张图在用例里都能一眼看全**,不用滚好几屏才过完一张
- 长截图点开后**字看得清**;核对时能在这个用例的截图之间**一张一张往下翻**,不用每看一张都关掉再找下一张
- 用例内容多时,能**收成一段一行的大纲**,在里面找到某一段、调顺序,点一下回到那一段
- 能在截图上**画红框**,标出点的是哪个按钮、要确认的是哪一处 —— 现在是导出之后在 Excel 里插四边形、去掉填充、边框改红,每导出一次就要重框一次。**导出后框在 Excel 里仍是能拖、能删的图形**,和手工做的一样;截图本身不被改动,框随时能删能改

**验收要点**

- 连续粘贴多张截图并补充说明,过程中不需要切换到其他软件
- 从 IDEA 的 database 工具复制一段查询结果,粘进来是一张表格而不是一段文字
- 加一段内容之后,**画面自动滚到它那里**,不用自己找
- 导出的 Excel 用 Excel / Numbers 打开时,sheet 名与用例编号一致,图片位置正确、不重叠、不溢出单元格
- **一个装了几十张高分辨率截图的 evidence,每一张都画得出来**,反复开关也不会有几张变成「この画像は表示できません」
- DB 结果里的 `007`、日期、长 ID 在 Excel 里显示成原样,没有被自动转成数字、日期或科学计数法
- 把工具导出的 sheet 和一份手工做的 evidence 并排看:**字体、表头、NULL 的颜色一致**,看不出是两个来源
- 值为 `≪ NULL ≫` 的单元格是灰色的
- 一段三行的日志,默认导出后在 Excel 里占三行;切到「合并」再导出,它在一个单元格里
- 复制一个用例后,新用例的内容与原用例逐段一致;**删掉复制出来的那个,原用例的截图仍然在**
- 复制之后可以马上改编号,不需要先接受一个自动生成的名字再去找重命名
- 在一个用例里打开 memo 侧栏、搜到一条、读完关掉,**当前用例和滚动位置一格没动**
- 侧栏开着时截图变窄了,但点一下能看原图
- 在笔记本屏幕上,一张普通截图和一张整页长截图,在用例里都**整张出现在一屏之内**,连同它的小标题
- 点开一张长截图:按宽度显示、能上下滚,字看得清;滚到头,后面的页面不跟着滚
- 灯箱里按 `→` 换到这个用例的下一张截图,文字和表格被跳过;翻到第 5 张关掉,**列表停在第 5 张**;不翻就关,列表一格不动
- 打开大纲,一个装了十几张截图的用例收进一屏;拖一行调顺序,拖着的是一行而不是一张图
- 在大纲里点一段,回到正常视图并停在那一段;点一张图的缩略图,直接在灯箱里打开它,关掉后还在大纲里;开着大纲切用例还是大纲,刷新后回到正常视图
- 在灯箱里拖一下就是一个红框,关掉后卡片上看得到;连着框一个用例里的几张图,不用每张都关掉再开
- 导出后用 Excel 打开,红框压在截图的对应位置上,点得中、拖得动、删得掉;Windows 的显示缩放下也不错位
- 复制一个用例,框跟着过去
- 停在第 3 个用例上按 `F5`,回来还是第 3 个用例
- 在第 3 个用例上点导航条的 Memo,看完再点 Evidence → **直接回到那第 3 个用例**
- 删掉那份 evidence 之后再点导航条的 Evidence → 回到列表,而不是一个打不开的页面
- 把一个表格改成文字,再改回表格,行列和原来一致
- 一段从来没被认出来过的 TSV 日志,点「转为表格」能变成表格;一段没有制表符的日志**看不到这颗按钮**
- 连着粘同一张截图两次,第二次会被问一句,而不是默默多出一个一样的 Block
- 完整走一遍「改完功能 → 粘贴截图 → 贴 DB 结果 → 补说明 → 导出 Excel」,耗时明显低于手工制作

> Evidence 的内容**没有步骤编号** —— 一个用例里的几段是分节(事前准备 / 画面 / 日志 / 结果),不是 1→2→3 的步骤,编号只会在插入一节时全部错位。每段改用一个可选的小标题。详见 [ADR-0003](./adr/0003-evidence-is-a-workbook.md)。
>
> Excel 的样式**不再是「工具自己定」**,基准是 a5m2 粘贴出来的结果,见 §3 与 [ADR-0011](./adr/0011-excel-style-follows-a5m2.md)。

### F6. 多语言界面(中文 / 日语)

**场景与痛点**
现在界面文案全是写死的中文。工作机在日本使用,界面如果能显示日语会更贴合使用场景;同时也希望能在同一台机器上按需切换语言(比如练习日语,或单纯喜好)。

**需求**

- 界面提供中文、日语两种语言,可在导航栏手动切换
- 首次打开时按浏览器语言自动选定一种作为默认,之后手动选过的语言被记住,下次打开沿用
- 切换语言后,导航、按钮、菜单、空状态提示、确认弹窗等界面文案随之切换;操作失败时看到的错误提示(比如「待办内容不能为空」)也随之切换
- 时间戳的显示格式跟随所选语言

**验收要点**

- 切到日语后,遍历 memo / todo / 书签 / evidence 的每个页面,看不到遗留的中文界面文案
- 触发一次会报错的操作(如提交空标题的待办、登记一条不存在的路径),错误提示是日语
- 刷新页面或重新打开浏览器,依然是上次选择的语言
- 一台从未打开过 workutil 的日文系统浏览器,首次打开默认即为日语;中文系统浏览器首次打开默认为中文

> 你自己在 memo / todo / 书签 / evidence 里输入的内容永远不翻译,原样显示。Evidence 导出的 Excel 文件名与内容也不受这个开关影响,见 design.md §6 F5。

### F7. 数据导出与导入(换电脑)

**场景与痛点**
换一台工作电脑时,几个月攒下来的 memo、待办、书签、evidence 要跟着走。数据本来就全在一个目录里,理论上「整个拷走就是完整的」—— 但那个目录在 Windows 上是 `%LOCALAPPDATA%\workutil`,得先知道它在哪、再手工翻进去;新机器上还要把东西放回同一个位置,而那个位置在工具第一次启动之前根本不存在。**结果是「理论上可行」和「换电脑那天真的做得成」之间差了一截。**

**需求**

- 一键把**全部数据**导出成一个文件,从浏览器下载下来
- 在新机器上一键导入那个文件,不必知道数据目录在哪
- 导入**不覆盖**已有数据 —— 只往空的工具里导

**验收要点**

- 导出得到一个文件,里面包含数据库和全部图片;体积和数据目录相当
- 在一台**全新**的机器上导入它,重开工具后 memo / 待办 / 书签 / evidence 一条不少,evidence 里的截图都在
- 往一台**已经有数据**的工具里导入,被明确拒绝,而不是悄悄合并或覆盖
- 用新版本导出的文件去导入旧版本的工具,被明确拒绝,而不是导进去之后打不开
- 导出的那一刻工具还在正常用,导出的文件**不是坏的**

> 这条原本在 §7 里被推迟,理由是「手动备份已可行」。真正要用的时候才发现,难的不是备份,是**在新机器上放回去**。
>
> **跨系统迁移(Windows → macOS)书签会全部失效** —— 书签存的是绝对路径,这是它本来的样子(见 [ADR-0006](./adr/0006-a-bookmark-is-an-entry-not-a-file.md)),不是导入的 bug。memo / 待办 / evidence 不受影响。
>
> 这不违反 §3「两台机器的数据各自独立,不同步」:那条讲的是**日常不同步**,而换电脑是一次性的搬家。工作机的数据搬到新工作机上,仍然没有离开工作环境。

## 5. 非功能需求

| 项目 | 要求 |
| --- | --- |
| **可扩展性** | 新增一个功能不应改动既有功能。这是第一约束 |
| **跨平台** | Windows 与 macOS 均可使用 |
| **数据保密** | 工作机产生的数据不离开工作机 |
| **安全** | 工具具备执行任意本地代码的能力(F3 书签可指向 `.bat` / `.exe` / `.command`,见 [ADR-0005](./adr/0005-bookmarks-are-a-second-code-execution-path.md)),必须不可被外部访问 |
| **部署简单** | **不安装**:下载一个 zip、解压、双击即可用,不要求工作机上预先有 Python、Node 或任何别的东西 |
| **响应速度** | 本地工具,操作应即时;不接受为了打开一条 memo 而等待 |
| **界面稳定** | 每个画面的有效区域**固定不变**:展开一条 memo、切换一个用例、弹出一条提示,都不应让页面框架伸缩或让别的内容被推走。内容变多只体现为内部滚动条变长 |

## 7. 明确不做(Backlog)

刻意推迟的需求。列在这里是为了说明「这不是漏了」。

| 项目 | 为什么推迟 |
| --- | --- |
| Memo 标签归类 | 归类本身就是录入负担,与「极低摩擦」冲突。等搜索真的不够用了再加 —— 那时才知道该按什么维度分。**置顶不是它的第一步**:置顶没有维度也没有名字,不需要在记录的那一刻做任何决定,见 [ADR-0008](./adr/0008-memo-can-be-pinned-but-not-categorised.md) |
| 导入现有记事本内容 | 一次性动作,手动复制粘贴即可,不值得写代码 |
| 两台机器之间的数据**合并** | F7 的导入只往空工具里导。合并要处理 id 冲突、图片重名、两边都改过同一条 —— 而 §3 说的就是两台机器各自独立,没有合并的场景 |
| 在 evidence 的 memo 侧栏里**新建** memo | 「做 evidence 时想起一件事随手记」是真实需求,但侧栏第一版只读:能编辑就意味着草稿那一套要在侧栏里再活一份,而删除/置顶挤在一条窄栏里是误触陷阱。等侧栏用出手感再加,见 [ADR-0013](./adr/0013-memo-panel-lives-inside-evidence.md) |
| Evidence 截图上的箭头、文字、圆圈 | 只要了红框。先把这一样做顺手,见 `.scratch/evidence-box/spec.md` |
| 全局热键快速录入 | 受浏览器形态限制,需要额外的原生入口。先验证浏览器形态是否真的不够快 |
| 书签的文件选择器 / 目录浏览器 | 浏览器不把本地绝对路径交给页面,唯一的实现方式是由后端列出本机目录 —— 那等于给这个服务加一个「列出任意目录」的能力。而登记是低频动作,粘贴路径够用 |
| F4 Python 脚本管理与执行 | 目前用得不多,直接开 IDE / 终端跑也够用;而且是全项目里最独立、最复杂的一块(流式输出、进程管理、中断)。等真的高频需要再做,原有的设计草案(design.md 历史版本)留在 git 里备查 |

## 8. 已知风险

- **「极低摩擦」尚未被真实验证**:浏览器标签页无法注册全局快捷键,实际录入路径是「切到浏览器 → 找到标签页 → 输入」,未必快过一直开着的记事本。这是第一版最大的产品风险,由 §4 F1 的行为验收标准来检验。
