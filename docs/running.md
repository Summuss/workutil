# 怎么跑起来

> 本文只讲**操作步骤**。为什么是这个形态见 [design.md](./design.md) §1 与 §7。

三个场景,别搞混:

| 场景 | 服务跑在哪 | 用哪个端口 | 什么时候用 |
| --- | --- | --- | --- |
| A. 开发 | 服务器 | 5173(Vite) | 改代码,要热更新 |
| B. 验收 | 服务器 | 8765(FastAPI) | 验的就是将来在工作机上跑的那个东西 |
| C. 使用 | 工作机 / 私人 Mac | 8765 | 日常真正用它 |

## 零、一次性准备(服务器)

```sh
cd ~/Code/summus-workutil
make install          # backend: uv sync;frontend: pnpm install
```

需要 [uv](https://docs.astral.sh/uv/) 和 Node + pnpm。服务器上都已经有了。

> Node 至少 **22.22.0**(react-router 8 的下限)。构建只发生在开发服务器上,
> 工作机拿到的是 `dist/`,所以这个下限不影响工作机。

> **所有 `make` 命令都在仓库根目录跑。** 在 `backend/` 里跑会得到
> `make: *** No rule to make target` —— Makefile 只有一份,在根目录。

## A. 开发(日常)

### 1. 从 macOS 开隧道

```sh
ssh -L 5173:127.0.0.1:5173 <你的服务器>
```

**只用转发 5173。** `/api` 由 Vite 在服务器端反代到 8765,不需要第二条隧道。

### 2. 在服务器上起两个进程

```sh
make dev-backend     # :8765,--reload
make dev-frontend    # :5173
```

要两个 shell。用 tmux 一步到位:

```sh
tmux new-session -d -s workutil 'make dev-backend'
tmux split-window -t workutil 'make dev-frontend'
tmux attach -t workutil
```

`Ctrl+b d` 脱离,`tmux attach -t workutil` 回去,`tmux kill-session -t workutil` 结束。

验证两个都活着:

```sh
tmux list-panes -t workutil        # 应该两个 pane,dead=0
curl -sS localhost:5173/api/memos  # 经 Vite 反代打到后端,通了就说明隧道够用
```

### 3. 在 macOS 浏览器打开

<http://localhost:5173>

改前端存盘即刷新;改后端 `--reload` 会自己重启。

## B. 验收(生产形态)

一个端口、一条命令,验的是最终形态:前端构建产物由 FastAPI 一并托管,单进程。

```sh
# macOS 上
ssh -L 8765:127.0.0.1:8765 <你的服务器>

# 服务器上
cd ~/Code/summus-workutil && make build && make run
```

打开 <http://localhost:8765>。

### UI 要人工看什么

第一版**刻意不写前端自动化测试**(见 `.scratch/memo/spec.md` Testing Decisions),
所以 UI 回归只能靠手动。唯一的例外是 Markdown 不解析 raw HTML 那条安全边界,
由 `MemoMarkdown.test.tsx` 守着,`make test` 会跑。其余每次动了前端,对着看一遍:

#### 界面外壳与固定布局(M5)

| 看什么 | 期望 |

#### Memo 编辑手感(M7)

**这一节整节都是为了守住同一件事:拖选复制不能被当成点击。** 前后已经为它回退过两次(点正文进编辑、整行按钮),第三次的入口是「点空白开合」。

| 看什么 | 期望 |
| --- | --- |
| 输入框里按 `Tab` | 打出一个**制表符**,光标不跳走 |
| 打几个 `Tab` 之后按 `Ctrl+Z` | **一下一下撤销回去**(用 `execCommand` 就是为了这个;若撤销失效说明退回了 `setState`) |
| 选中一段文字再按 `Tab` | 选区被一个制表符替换,**不是**给每行加缩进 |
| 输入框里按 `Esc`,再按 `Tab` | 内容**不清空**,焦点离开输入框,`Tab` 恢复正常移焦 |
| 展开态编辑区里按 `Tab` / `Esc` | `Tab` 同上;`Esc` 仍是「退回渲染态、草稿保留、头部标未保存」的既有行为 |
| **Evidence 的输入框里按 `Tab`** | 行为**不变**(焦点移走)—— 制表符是它判断表格的判据,刻意没做 |
| 点折叠行文字右边那片空白 | 展开 |
| 点展开卡片的边缘 / 正文下方的空白 | 折叠 |
| **拖选一段正文,在空白处松手** | 选得中、能复制,**不折叠**(两个条件缺一不可,这条最容易坏) |
| 双击正文里的一个词 | 选中那个词,**不折叠** |
| 点段落右侧那片看起来是空白的地方 | **什么都不发生** —— 已知代价,那片在 DOM 上属于 `<p>`,见 design.md §6 F1 |
| 编辑到一半点卡片空白 | **不折叠**,草稿还在 |
| 折叠态点「编辑」图标 | 一步展开并进入编辑态,光标落末尾 |
| 从折叠态进编辑、改几个字存下 | **留在展开态**,能看见刚存的内容 |

| 已有 `abc` 时填 `ABC` | 也被拒 —— Excel 的 sheet 名不分大小写,而 openpyxl 会**不吭声地**写成 `ABC1` |
| 在另一份 Evidence 里也填 `1` | 能存下(重名只在同一份里不允许) |
| 双击某个标签 | 就地改名,`Enter` 存下,`Esc` 放弃 |
| 点工具栏的「复制用例」按钮 | 复制一个含文字 / 图片 / 表格三种 Block 的用例,副本逐段一致 |

| 重命名复制后的用例,改成一个已存在的编号 | 被拒,提示与现有重命名一致,输入框留在原地 |
| 删掉复制出来的用例,去 `images/evidence/<id>/` 查看磁盘文件 | **原用例的图片文件仍在**,副本生成的新图片文件已被清理 |
| 日语界面下看复制按钮及错误提示 | 按钮提示为「ケースを複製」,失败提示为日语 |
| 按住某个用例标签的拖拽把手拖动 | 浮层跟随光标移动、原位留占位空槽,松手后落在新位置,「第 N / M 个 sheet」跟着变 |
| 键盘:`Tab` 到拖拽把手,空格拾起、方向键移动、空格放下 | 同样能重新排列 |
| 点 `⇤` / `⇥` | 一步挪到最前 / 最后 |
| 已在最前时看 `⇤`、已在最后时看 `⇥` | 是灰的,点不动 |
| 删掉当前用例并确认 | 标签消失,自动落到接替它位置的那个,内容区不会空着 |

| 在列表页删掉一整份并确认 | 从列表消失,`images/evidence/<id>/` 也一并没了 |

| 在有数据的库上点「导出数据」 | 下载一个 zip;解开看得到 `workutil.db`、`images/`、一份清单 |
| 导出时旁边开着一个正在写的会话 | 导出的库能正常打开,不是坏的 |
| `WORKUTIL_DATA_DIR=/tmp/fresh make run`,进设置点「导入数据」选那个 zip | 提示成功,并明确告诉你**要重启** |
| 重启后看四个页面 | memo / 待办 / 书签 / evidence 一条不少,evidence 的截图都在 |
| **在刚导入过(非空)的库上再导入一次** | **被拒绝**,提示已有数据 |
| 手工把库清空但留着 `images/` 里的文件,再导入 | **被拒绝** —— 「库空但图片还在」是上次失败的现场 |
| 改一下 zip 里清单的 revision 再导入 | **被拒绝**,提示版本不匹配 |
| 导入之后看数据目录 | 多一个 `workutil.db.bak-<时间戳>` |
| 日语界面下走一遍导出导入 | 按钮、成功提示、三条拒绝提示都是日语 |

## C. 在工作机 / 私人 Mac 上使用

工作机不需要预装 Python、Node 或任何开发工具。直接从 GitHub Releases 下载预先组装好的解压即用便携包。

### 1. 下载便携包

从仓库 Releases 页面下载对应系统的压缩包:
- Windows (x64): `workutil-<version>-windows-x64.zip`
- macOS (Apple Silicon): `workutil-<version>-macos-arm64.zip`

### 2. 解压前解除锁定 (重要:仅 Windows)

从网络下载的 zip 文件会带有 Windows Mark-of-the-Web (MOTW) 区域安全标记。**在解压之前必须先解除锁定**,否则解压出的批处理脚本与依赖可能被系统阻止运行:

1. 右键下载的 `workutil-<version>-windows-x64.zip` 文件,选择 **「属性」**。
2. 在常规选项卡最下方,勾选 **「解除锁定」** (Unblock)。
3. 点击 **「确定」**。

之后将 zip 解压到任意你喜欢的目录(例如 `D:\tools\workutil\` 或个人主目录)。

### 3. 双击运行

- **Windows**: 双击解压目录下的 `workutil.bat`。
- **macOS**: 双击解压目录下的 `workutil.command`。

启动脚本会在后台启动后端服务(`127.0.0.1:8765`),并自动调起无地址栏、无标签栏的独立 app 模式窗口。
如果 workutil 已经在运行,再次双击启动脚本**不会产生冲突错误或启动重复服务**,而是会自动将已有窗口唤起到前台,进程以退出码 0 正常退出。

### 4. 安装为应用与开机自启 (推荐)

借助 Web Manifest 支持,可以在 Edge / Chrome 中将其固化为独立桌面应用:

1. **安装为应用**:
   - 在独立窗口或 Edge 中访问时,点击地址栏右侧的「应用」图标(或右上角菜单 `...` → **「应用」** → **「将此站点作为应用安装」**)。
   - 安装完成后,系统开始菜单中会出现 **workutil** 图标,可直接固定到任务栏或桌面。
2. **设置开机自启**:
   - 打开 Edge 浏览器,在地址栏输入 `edge://apps` 进入应用管理。
   - 找到 **workutil**,点击右侧 `...` 菜单(或右键)。
   - 勾选 **「在设备登录时自动启动」** (Auto-start on device login)。
   - 这样每天开机时 workutil 便会自动在后台或独立窗口中就绪。

### 5. 版本更新

- **数据去哪了**: 数据保存在系统标准数据目录下(Windows: `%LOCALAPPDATA%\workutil`, macOS: `~/Library/Application Support/workutil`),不在解压文件夹内部。
- **如何升级**: 下载新版本 zip 并解除锁定后,**直接删掉旧的 workutil 文件夹、解压新版本即可**。所有既有的 Memo、Todo、书签与 Evidence 数据零丢失、完全不受影响。

### 6. 换电脑:把数据搬过去

在**旧**机器上:

1. 打开 workutil,点导航栏右侧的齿轮进 **设置**。
2. 点「导出数据」,浏览器下载一个 `workutil-data-<日期>.zip`。里面是数据库 + 全部图片 + 一份清单(版本号、条数)。
3. 把这个 zip 拷到新机器上(U 盘、共享盘,随便)。

在**新**机器上:

1. 先按前面几节把便携包跑起来,**至少打开一次**(这一步会建出数据目录)。
2. **不要先用它记东西** —— 导入只允许在工具还是空的时候执行。
3. 进 **设置** → 「导入数据」→ 选那个 zip。
4. 导入成功后**关掉 workutil 再重新打开**。不重启看到的还是旧状态。

几件会让你卡住的事:

- **新机器上已经记过东西了 → 导入会被拒绝。** 这是有意的:合并数据要处理 id 冲突和图片重名,工具不做(requirements.md §7)。真要导,先把数据目录整个挪走再重开一次工具。
- **旧机器版本比新机器新 → 导入会被拒绝。** 数据库迁移只能向前走,硬导进去的结果是一个打不开的库。先把新机器上的 workutil 升到同版本或更新。
- **Windows → macOS 搬家,书签会全部失效。** 书签存的是绝对路径(`C:\...` 在 macOS 上不存在),这是它本来的样子,不是导入出了问题。memo / 待办 / evidence 不受影响,书签重新登记即可。
- 导入前工具会把新机器上那个空库改名成 `workutil.db.bak-<时间戳>` 留在数据目录里。确认没问题之后可以自己删掉。

### 落差:有些东西在服务器上验不了

开发时服务跑在 Linux 服务器上,以下行为**必须拿到 Windows / macOS 本机上测**:

1. **F3 书签「用默认程序打开文件」** —— 服务器无桌面环境,只能由 fake platform 覆盖参数逻辑。
2. **便携包启动与独立 app 模式窗口** —— 包括批处理拉起 standalone Python、浏览器 `--app` 模式的唤起与 PWA 安装效果。

## 数据在哪

| 平台 | 位置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\workutil` |
| macOS | `~/Library/Application Support/workutil` |
| Linux | `~/.local/share/workutil` |

里面是 `workutil.db` 和 `images/`,目录内部只用相对路径。
`images/` 下 Memo 一条一个目录、目录名就是它的 id(`images/12/`),
Evidence 的在 `images/evidence/<id>/` —— memo 的目录名永远是十进制整数,
不会和字面量 `evidence` 撞上(design.md §5)。
**把这个目录整个拷走就是一份完整备份。** 但换电脑时别这么做 —— 用设置页的
导出 / 导入(上面「换电脑:把数据搬过去」一节)。手工拷贝有两个坑:①拷的时候
工具可能正在写库,拿到的副本可能是坏的(导出走 SQLite 的 backup API,不会);
②新机器上那个目录在工具第一次启动之前根本不存在,你得先猜对位置。

设环境变量 `WORKUTIL_DATA_DIR` 可以指向别处 —— 开发时想要一份干净的库很方便,
试出来的垃圾数据不会混进真正在用的那份:

```sh
WORKUTIL_DATA_DIR=/tmp/workutil-scratch make run
```

清掉试出来的单条记录可以直接在展开的卡片头部点「删除」;如果要整库重置,删库文件即可:

```sh
rm ~/.local/share/workutil/workutil.db     # 下次启动会自动重建
```

## 出问题时

**浏览器打不开** —— 十有八九是隧道断了,不是服务挂了。先在服务器上确认服务活着:

```sh
curl -sS localhost:8765/api/memos
```

有输出就说明服务没问题,重开 `ssh -L` 即可。

**端口被占** —— 上一次的进程没退干净:

```sh
ss -tlnp | grep -E '5173|8765'
pkill -f 'uv run workutil'; pkill -f uvicorn
```

**局域网里另一台机器访问不了** —— 这是设计如此,不是故障。服务只绑 `127.0.0.1`,
因为它后续会具备执行任意本地 Python 的能力(requirements.md §5)。所以必须走 SSH 端口转发,
Tailscale IP 也进不来。
