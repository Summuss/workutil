# 怎么跑起来

> 本文只讲**操作步骤**。为什么是这个形态见 [design.md](./design.md) §1 与 §7。

三个场景,别搞混:

| 场景 | 服务跑在哪 | 用哪个端口 | 什么时候用 |
| --- | --- | --- | --- |
| A. 开发 | 服务器 | 5173(Vite) | 改代码,要热更新 |
| B. 验收 | 服务器 | 8765(FastAPI) | 验的就是将来在工作机上跑的那个东西 |
| C. 使用 | 工作机 / 私人 Mac | 8765 | 日常真正用它 |

## 零、一次性准备(服务器)

```sh
cd ~/Code/summus-workutil
make install          # backend: uv sync;frontend: pnpm install
```

需要 [uv](https://docs.astral.sh/uv/) 和 Node + pnpm。服务器上都已经有了。

> Node 至少 **22.22.0**(react-router 8 的下限)。构建只发生在开发服务器上,
> 工作机拿到的是 `dist/`,所以这个下限不影响工作机。

> **所有 `make` 命令都在仓库根目录跑。** 在 `backend/` 里跑会得到
> `make: *** No rule to make target` —— Makefile 只有一份,在根目录。

## A. 开发(日常)

### 1. 从 macOS 开隧道

```sh
ssh -L 5173:127.0.0.1:5173 summus@192.168.3.3
```

**只用转发 5173。** `/api` 由 Vite 在服务器端反代到 8765,不需要第二条隧道。

### 2. 在服务器上起两个进程

```sh
make dev-backend     # :8765,--reload
make dev-frontend    # :5173
```

要两个 shell。用 tmux 一步到位:

```sh
tmux new-session -d -s workutil 'make dev-backend'
tmux split-window -t workutil 'make dev-frontend'
tmux attach -t workutil
```

`Ctrl+b d` 脱离,`tmux attach -t workutil` 回去,`tmux kill-session -t workutil` 结束。

验证两个都活着:

```sh
tmux list-panes -t workutil        # 应该两个 pane,dead=0
curl -sS localhost:5173/api/memos  # 经 Vite 反代打到后端,通了就说明隧道够用
```

### 3. 在 macOS 浏览器打开

<http://localhost:5173>

改前端存盘即刷新;改后端 `--reload` 会自己重启。

## B. 验收(生产形态)

一个端口、一条命令,验的是最终形态:前端构建产物由 FastAPI 一并托管,单进程。

```sh
# macOS 上
ssh -L 8765:127.0.0.1:8765 summus@192.168.3.3

# 服务器上
cd ~/Code/summus-workutil && make build && make run
```

打开 <http://localhost:8765>。

### UI 要人工看什么

第一版**刻意不写前端自动化测试**(见 `.scratch/memo/spec.md` Testing Decisions),
所以 UI 回归只能靠手动。唯一的例外是 Markdown 不解析 raw HTML 那条安全边界,
由 `MemoMarkdown.test.tsx` 守着,`make test` 会跑。其余每次动了前端,对着看一遍:

| 看什么 | 期望 |
| --- | --- |
| **打开 <http://localhost:8765/>** | 直接就是 Memo 页,**光标已经在输入框里** —— 加了路由之后这条最容易坏,先看它 |
| 点顶部「Evidence」再点回「Memo」 | 两页互切,当前那个在导航里高亮;回到 Memo 时光标又在输入框里 |
| 在 Evidence 页按浏览器后退 / 前进 | 在两页间来回,地址栏跟着变 |
| 在 `/evidence` 上按 `F5` | 还是 Evidence 页,**不是 404**(后端的 SPA 回退,design.md §3.1) |
| 地址栏敲一个不存在的路径 | 落回 Memo 页,不是白屏 |
| 打几个字,`Ctrl+Enter` | 立刻出现在下方列表最上面,只显示首行 |
| 保存之后 | 输入框空了,而且**还是聚焦的**,可以直接接着打下一条 |
| 连记三条 | 最新的在最上面 |
| `F5` 刷新 | 都还在,顺序不变 |
| 记一条多行的(粘段报错堆栈) | 列表里只显示第一行,不是整坨 |
| 只打空格然后 `Ctrl+Enter` | 什么都不发生,不产生空记录 |
| **保存后马上接着打字** | 已保存的那段不会赖在框里(否则下次保存会存重复) |
| 点列表里某条 | 就地展开,地址栏不变;正文是**渲染后**的 Markdown,代码块等宽带高亮 |
| 只用键盘:`Tab` 到某条按 `Enter` | 能展开;再 `Tab` 到「编辑」按 `Enter` 能进编辑 |
| **在展开的正文上拖选一段文字** | 选得中、能复制,**不会跳进编辑态**(这条是从真实使用里退回来的) |
| 点头部的「编辑」 | 正文换成纯文本框,光标落在末尾 |
| 改几个字 `Ctrl+Enter` | 存下,退回渲染态,头部出现「修改于」 |
| 改完按 `Esc` | 退回渲染态但**草稿还在**,头部标「未保存」,点回去还是那些字 |
| 编辑一条旧的再存 | 它**留在原位**,不会被顶到最上面 |
| 点头部的「删除」并确认 | 该条从列表中消失,刷新后依然不在 |
| 粘贴截图 / 拖入图片文件 | 插入光标位置,保存后列表中显示「含 1 张图」标记 |
| 展开含图 Memo | 正文内联展示原图,不走路由跳转 |
| 编辑含图 Memo 追加新截图 | 存下后新旧图片共存,列表更新为「含 2 张图」 |
| 正文里写 `<script>alert(1)</script>` | 原样显示成文字,不弹窗 |
| 搜一个词 | 列表收敛为命中的几条,每条在首行下方显示命中片段,关键词高亮 |
| 搜中日文两字词(`バグ` / `中文` / `対応`) | 都能命中 —— 这是 ADR-0002 的手动复核,后端也有测试守着 |
| 搜一个正文里出现很多次的词 | 最多显示 5 段片段,下面接一行「还有 N 处命中未显示」 |
| **拖选搜索结果里的片段** | 选得中、能复制(片段刻意放在按钮外面) |
| 搜一个不存在的词 | 明确提示「没有找到匹配「…」的 Memo」,不是空白 |
| 搜索框按 `Esc` 或点 ✕ | 立刻回到完整的时间倒序列表 |
| **搜索状态下记一条新 memo** | 不含关键词就不会挤进结果里;含关键词则带着片段出现 |
| 搜索框里快速连打一串字 | 一个字都不丢(曾经会被状态回环吃掉) |

macOS 上 `Cmd+Enter` 等价于 `Ctrl+Enter`。

#### Evidence(M2,组织层)

Evidence 与 Case 这两层 —— 用例**里面**的内容看下一节:

| 看什么 | 期望 |
| --- | --- |
| 顶部点「Evidence」 | 一个新建框加一份列表;**没有搜索框**(ADR-0001 把搜索划给 Memo,不是漏做) |
| 起个名字点「新建」 | 立刻出现在列表最上面,显示「0 个用例」和创建时间 |
| 名字只打空格再新建 | 被拒,红字提示,不产生空的 Evidence |
| 点列表里的标题 | 进 `/evidence/<id>`,地址栏跟着变 |
| 在详情页按 `F5` | 还是这份 Evidence,**不是 404** |
| 按浏览器后退 | 回到列表页 |
| 点详情页的标题 | 就地变输入框,改完 `Enter` 存下,`Esc` 放弃 |
| 点「+ 用例」填 `1` | 出现一个标签并选中,下方提示这个用例还是空的 |
| 再加 `2`、`2~5` | 依次排在后面;`2~5` 能正常存下(用例编号不一定是数字) |
| 填一个 32 字符的编号 | 被拒,提示「最多 31 个字符」,输入框**留在原地、字还在**,可以直接改 |
| 填 `検索: 一覧` 或带 `\ / ? * [ ]` 的 | 被拒,提示不能包含哪个字符 —— 这几个 Excel 不接受,导出时才发现就晚了 |
| 填一个已经有的编号 | 被拒,提示这份 Evidence 里已经有了 |
| 已有 `abc` 时填 `ABC` | 也被拒 —— Excel 的 sheet 名不分大小写,而 openpyxl 会**不吭声地**写成 `ABC1` |
| 在另一份 Evidence 里也填 `1` | 能存下(重名只在同一份里不允许) |
| 双击某个标签 | 就地改名,`Enter` 存下,`Esc` 放弃 |
| 选中一个用例点 `←` / `→` | 标签左右挪一位,「第 N / M 个 sheet」跟着变 |
| 点 `⇤` / `⇥` | 一步挪到最前 / 最后 |
| 已在最前时看 `←` 和 `⇤` | 是灰的,点不动 |
| 删掉当前用例并确认 | 标签消失,自动落到接替它位置的那个,内容区不会空着 |
| `F5` 刷新 | 用例和顺序都还在 |
| 在列表页删掉一整份并确认 | 从列表消失,`images/evidence/<id>/` 也一并没了 |

#### Evidence(M2,文字 Block)

用例里的一段一段内容。表格是 ticket 06,这里是文字 —— 日志也是文字,
不单列一类(design.md §6 F5):

| 看什么 | 期望 |
| --- | --- |
| 选中一个用例,在下方框里写一段按 `Ctrl+Enter` | 上面多出这一段,框清空,可以接着写下一段 |
| 只打空格再 `Ctrl+Enter` | 被拒,红字「这一段是空的 —— 不要的话删掉它」,字还在框里 |
| 粘一段前后带空行、每行都有缩进的日志 | 首尾空行没了,**每行的缩进都还在**(第一行也是) |
| 点某段的「+ 小标题」填「事前準備の DB データ」 | 变成一行加粗小标题;再点它能改,清空即去掉 |
| 点某段的「编辑」改完 `Ctrl+Enter` | 就地存下;`Esc` 放弃 |
| 拖选段落里的文字复制 | 选区不会因为松开鼠标就消失 —— 编辑是按钮而不是点正文,理由见 design.md §6 F1 |
| 点某段的 `↑` / `↓` | 与相邻那段换位 |
| 点 `⤒` / `⤓` | 一步挪到最前 / 最后 |
| 看第一段的 `↑` `⤒`、最后一段的 `↓` `⤓` | 都是灰的,点不动 |
| 删掉一段并确认 | 只有那一段消失,其余顺序不变 |
| `F5` 刷新 | 段落、小标题、顺序都在 |
| 切到另一个用例再切回来 | 两个用例的内容互不串台 |
| 删掉一个用例 | 它名下的段落跟着消失 |

#### Evidence(M2,图片 Block)

截图。删除规则和 Memo 相反(为什么见 design.md §5),下表最后四行看的就是这条:

| 看什么 | 期望 |
| --- | --- |
| 在下方的框里 `Ctrl+V` 粘一张截图 | 上面多出一个图片段,图就显示在里面,框里不会多出一串文字 |
| 一次粘 3 张(或选中 3 个图片文件拖进框里) | 出来 3 个独立的段,顺序和粘贴顺序一致 |
| 把一个图片文件拖到框里 | 同上,变成一个图片段 |
| 给图片段点「+ 小标题」 | 和文字段一样能加、能改、能清空 |
| 图片段的 `↑` `↓` `⤒` `⤓` | 和文字段混在一起也能正常换位 |
| 看图片段的按钮 | **没有「编辑」** —— 图片是重拍重粘的,不是改的 |
| 很宽的截图 | 缩到卡片宽度显示,不会把页面撑出横向滚动条 |
| `F5` 刷新 | 图片还在,小标题和顺序也在 |
| 粘完看 `images/evidence/<id>/` | 多出 `img_N.png`,**和粘进去的原图一模一样大**(不压缩;缩放只发生在导出时) |
| 删掉一个图片段并确认 | 段没了,**那个文件也从 `images/evidence/<id>/` 里消失**,同目录其他图还在 |
| 删掉一个有图的用例 | 它名下的图片文件消失,**其他用例的图还在**(一份 Evidence 的所有用例共用一个目录) |
| 在列表页删掉整份 | `images/evidence/<id>/` 整个目录没了 |

在 macOS / Windows 上再走一步(服务器上验不了):用看图软件打开一张
`images/evidence/<id>/` 下的图,不关它,回来删那个段 —— **删除照样成功**,
只是文件可能留在磁盘上(design.md §5)。

## C. 在工作机 / 私人 Mac 上使用

```sh
make build   # 构建前端(需要 Node)
make run     # 启动
```

打开 <http://127.0.0.1:8765>。

**运行时只需要 Python(uv),不需要 Node** —— 前端已经是构建好的静态文件
(design.md §3.1)。但 `frontend/dist/` 不进版本库,所以目标机上要么自己
`make build` 一次(那就需要 Node),要么把 `dist/` 拷过去。

> ⚠️ **最终分发方式还没定**,取决于工作机允不允许装软件(requirements.md §6)。
> 若不允许,退路是 uv 自带 Python + PyInstaller 打包(design.md §3.2),届时这一节要重写。

### 落差:有些东西在服务器上验不了

开发时服务跑在 Linux 服务器上,所以后续里程碑的这些行为**必须拿到 Windows / macOS 本机上测**:

- F3 书签「用默认程序打开文件」—— 在服务器上会去开服务器的文件,而服务器没有桌面
- F4 脚本执行 —— 跑的是服务器上的 Python

UI、数据存取、Excel 导出可以在服务器上完整验证。详见 design.md §7、§9。

## 常用命令

| 命令 | 做什么 |
| --- | --- |
| `make install` | 装两端依赖 |
| `make dev-backend` | 后端 :8765,热重载 |
| `make dev-frontend` | 前端 :5173,`/api` 反代到后端 |
| `make build` | 构建前端到 `frontend/dist/` |
| `make run` | 生产形态启动(单进程,含 UI) |
| `make test` | 后端测试 + 前端那一个渲染安全测试 |
| `make check` | ruff check + ruff format --check + mypy + tsc |

改了 ORM 模型之后要生成迁移:

```sh
cd backend && uv run alembic revision --autogenerate -m "描述"
```

迁移**随服务启动自动执行**,不用手动 `upgrade`。生成后过一眼再提交。

## 数据在哪

| 平台 | 位置 |
| --- | --- |
| Windows | `%APPDATA%\workutil` |
| macOS | `~/Library/Application Support/workutil` |
| Linux | `~/.local/share/workutil` |

里面是 `workutil.db` 和 `images/`,目录内部只用相对路径。
`images/` 下 Memo 一条一个目录、目录名就是它的 id(`images/12/`),
Evidence 的在 `images/evidence/<id>/` —— memo 的目录名永远是十进制整数,
不会和字面量 `evidence` 撞上(design.md §5)。
**把这个目录整个拷走就是一份完整备份**,不需要工具提供导出功能。

设环境变量 `WORKUTIL_DATA_DIR` 可以指向别处 —— 开发时想要一份干净的库很方便,
试出来的垃圾数据不会混进真正在用的那份:

```sh
WORKUTIL_DATA_DIR=/tmp/workutil-scratch make run
```

清掉试出来的单条记录可以直接在展开的卡片头部点「删除」;如果要整库重置,删库文件即可:

```sh
rm ~/.local/share/workutil/workutil.db     # 下次启动会自动重建
```

## 出问题时

**浏览器打不开** —— 十有八九是隧道断了,不是服务挂了。先在服务器上确认服务活着:

```sh
curl -sS localhost:8765/api/memos
```

有输出就说明服务没问题,重开 `ssh -L` 即可。

**端口被占** —— 上一次的进程没退干净:

```sh
ss -tlnp | grep -E '5173|8765'
pkill -f 'uv run workutil'; pkill -f uvicorn
```

**局域网里另一台机器访问不了** —— 这是设计如此,不是故障。服务只绑 `127.0.0.1`,
因为它后续会具备执行任意本地 Python 的能力(requirements.md §5)。所以必须走 SSH 端口转发,
Tailscale IP 也进不来。
