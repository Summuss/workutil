# Spec: Evidence(M2)

Status: ready-for-agent

## Problem Statement

改完一个功能之后要做验证,验证过程要整理成 evidence 交出去。

一个 evidence 文件对应**一批测试用例**,每个用例占 Excel 的一个 sheet,sheet 名是用例编号(`1`、`2`、`2~5`,不一定是数字)。一个用例里通常有四段东西:事前准备的 DB 数据、画面截图、日志输出、DB 更新后的结果 —— 也就是**文字、图片、表格**三种内容。

现在这些全靠手工:截图存成文件再插进 Excel、调整行高列宽让它不重叠、从 DB 客户端复制结果粘进去再手动调格式,还要提防 Excel 把 `007` 变成 `7`、把 `2024-01-01` 变成日期序列号。做一份 evidence 的时间里,真正在验证的部分很少。

## Solution

在工具里开一份 Evidence,加几个 Case(用例),在每个 Case 里一路粘下去。

截图 `Ctrl+V` 直接成为一个图片块。从 IDEA 的 database 工具复制一段查询结果 `Ctrl+V`,它认出这是表格,变成一张保持行列结构的表 —— 而不是一坨对不齐的文字;认错了(比如一段带缩进的日志)旁边有一句「识别为表格,8 行 5 列 · 改为纯文字」,点一下就改回来。每段内容可以加个小标题,顺序可以上下调。

做完点导出,拿到一个 `エビデンス_<title>.xlsx`:一个用例一个 sheet,sheet 名就是用例编号,图片位置正确不重叠,DB 结果原样呈现、没有一个值被 Excel 擅自改写。

## Domain Model

三层,术语见 `CONTEXT.md`:

```
Evidence { id, title, created_at, updated_at }            一个 xlsx 文件
  └─ Case  { id, evidence_id, name, order }               一个测试用例 = 一个 sheet
       └─ Block { id, case_id, order, kind, label?, ... } 用例里的一段内容
```

`Block.kind` 是 `text` / `image` / `table`。**没有步骤编号** —— 一个用例里的几段是分节,不是 1→2→3(见 ADR-0003)。

## User Stories

### 组织

1. 作为开发者,我希望新建一份 Evidence 并给它起个名字,这样我知道这份是给哪次修改做的。
2. 作为开发者,我希望在一份 Evidence 里加多个 Case,这样一批测试用例能出在同一个文件里。
3. 作为开发者,我希望 Case 的名字就是测试用例编号、可以是任意文字(`2~5`),这样导出后 sheet 名和用例表对得上。
4. 作为开发者,我希望非法的 sheet 名在我输入时就被拦住,这样我不会在导出后才发现 Excel 打不开。
5. 作为开发者,我希望调整 Case 的先后,这样 sheet 顺序和用例顺序一致。
6. 作为开发者,我希望删掉一个 Case,这样试错的用例不会跟着交付出去。
7. 作为开发者,我希望看到已有的 Evidence 列表并回到其中一份继续做,这样我可以分两天做完一份。

### 录入

8. 作为开发者,我希望在一个 Case 里连续粘贴,过程中不需要切换到其他软件。
9. 作为开发者,我希望粘贴截图直接变成一个图片块,不需要先存成文件。
10. 作为开发者,我希望从 IDEA 的 database 工具复制的查询结果粘进来是一张**保持行列结构**的表格。
11. 作为开发者,我希望工具认错内容类型时能一键改正,这样一段带缩进的日志不会被硬塞成表格。
12. 作为开发者,我希望给每段内容加一个小标题(「事前準備の DB データ」),这样导出后别人看得懂每段是什么。
13. 作为开发者,我希望调整段落顺序,包括把一段直接挪到最前或最后。
14. 作为开发者,我希望删掉一段内容,这样重拍的截图不会留在交付物里。
15. 作为开发者,我希望能标记表格的第一行是不是表头,这样不管我的 DB 客户端有没有带表头出来都对。
16. 作为开发者,我希望能删掉表格里不该交付的列、改掉需要打码的单元格。
17. 作为开发者,我希望**不能**给表格加行加列 —— 数据来自 DB,能手工加行就意味着 evidence 里可以出现编造的数据。

### 导出

18. 作为开发者,我希望一键导出成一个 Excel 文件,一个 Case 一个 sheet。
19. 作为开发者,我希望导出的 Excel 里图片位置正确、不重叠、不溢出。
20. 作为开发者,我希望 DB 结果里的 `007`、日期、长 ID **原样显示**,没有被转成数字、日期或科学计数法。
21. 作为开发者,我希望表格的表头一眼可辨(加粗 + 底色),这样交出去的东西是能读的。
22. 作为开发者,我希望导出的文件名一看就知道是什么,不用改名就能交。
23. 作为开发者,我希望改一版就能重导一次,这样发现漏了一张截图不用重做。

### 界面与数据

24. 作为开发者,我希望 memo 和 evidence 在同一个工具里切换,并且**打开工具时依然直接是 memo 的输入框**、光标已经在里面 —— 加功能不能把 F1 的零导航点击弄丢。
25. 作为开发者,我希望浏览器的前进后退在 evidence 里可用,这样从某个 Case 退回列表是自然的。
26. 作为开发者,我希望删掉 Evidence 时它的截图一并清掉,这样磁盘不会堆积交付完就没用的原图。

## Implementation Decisions

完整推导在 `docs/design.md` §6 F5,这里只列结论与它们的理由。

### 模型

- 三层 Evidence → Case → Block。**不是两层** —— 一个 evidence 文件对应一批用例,少掉中间层就变成一个用例一个文件(ADR-0003)。
- Block 有 `kind`(`text` / `image` / `table`)与可选 `label`。**Log 归进 `text`,不单列一类。没有步骤编号。**
- 一个 image Block 装一张图;一次粘 3 张 = 3 个 Block。
- 排序用 `order` 字段,交互是**上下移动 + 置顶 / 置底,不做拖拽**。

### 图片

- 先把 `_decode_image` / `_save_images` / `count_images` / `_discard_images` 从 `modules/memo/service.py` 提到 `core/images.py`,参数化「目录 + URL 前缀」。ADR-0001 说的「共享机制、不共享概念」就落在这里。
- 存 `data/images/evidence/<evidence_id>/`。memo 的目录名永远是十进制整数,不会和字面量 `evidence` 相撞,**所以不搬迁既有数据**。
- **删除规则和 memo 相反,而且是有理由的相反**:memo 不做引用计数是因为引用藏在 Markdown 正文里、剪切有中间态;Evidence 的引用是结构化的(一个 image Block 一张图),没有中间态,所以删 Block 即删文件、删 Case 即删其名下图片、删 Evidence 即删整个目录。沿用「删不掉文件不算失败」。

### 表格

- **解析放后端**,前端原样 POST 剪贴板文本。它是本模块边界矩阵最大的纯函数,放后端就落进既有 HTTP 主接缝,不必为它破「前端不写自动化测试」。
- TSV 是主路径,`text/html` 是兼容。实测 IDEA 的 database 工具**只放 `text/plain`**。
- 存 `rows: string[][]` + `has_header`,粘贴时解析定型 —— DB 的文本字段可能含制表符,粘贴那一刻是唯一还知道单元格边界的时候。
- `has_header` 默认 `true` 且一键可翻转,**不靠猜**:带不带表头取决于用户 IDEA 里的 TSV 格式设置。
- 能删行、删列、改单元格。**刻意不给加行加列。**

### 粘贴时的类型判别

有图片 flavor → image;`text/plain` 多行、含制表符、各行列数一致 → table;否则 → text。一定会误判,所以生成后挂一条**可无视的确认提示**(「识别为表格,8 行 5 列 · 改为纯文字」)。

### Excel 导出

- sheet 名 = Case 名,**合法性在录入时校验,不在导出时清洗**(sheet 名是交付内容,悄悄改名等于交一个没被检查过的文件)。约束:非空、≤31 字符、不含 `: \ / ? * [ ]`、同 Evidence 内不重名。**openpyxl 只对非法字符抛错,超长仅 warn 并原样写入**,长度这关必须自己把。
- 排布**单列纵向**,Block 之间空一行,label 加粗单占一行。
- **图片不撑行高,而是按 `N = ceil(高px / 20)` 预留 N 行**。Excel 行高上限 409 磅 = 545 px,截图基本都超,撑行高这条路是死的。
- 宽度等比缩到最大宽度(默认 900 px),**只作用在导出的那一份上,磁盘原图不动**。
- 表格:表头加粗 + 底色 `#87e7ad` + 全表细边框。**不用 Excel Table** —— 它强制列名唯一,DB join 出的两个 `id` 会被自动改名。
- **所有单元格统一 `@` 文本格式**。代价是绿色三角,接受(ADR-0004)。
- 排版参数集中在一个 `LayoutSettings` dataclass,值写在代码里,**第一版不做配置文件**。
- 文件名 `エビデンス_<title>.xlsx`,title 里的文件名非法字符替换为 `_`。非 ASCII,`Content-Disposition` 必须用 RFC 5987 的 `filename*=UTF-8''...`。
- 零个 Case 的 Evidence **拒绝导出**;零个 Block 的 Case **允许**,出一个空 sheet。

### 前端

- 引入 **react-router**。`/` 仍直达 memo 且**打开即聚焦输入框** —— 加路由不能把 F1 的零导航点击弄丢。
- Evidence 列表创建时间倒序,固定上限,**不做搜索**(ADR-0001 把搜索划给了 Memo)。

## Testing Decisions

| 位置 | 测? | 理由 |
| --- | --- | --- |
| HTTP API | ✅ **主接缝** | Evidence / Case / Block 的增删改与排序、TSV 解析、图片落盘与级联删除 |
| 导出的 xlsx | ✅ **走主接缝** | 调导出接口拿 bytes,用 openpyxl 读回来断言 sheet 名、单元格值、图片数量与锚定行。**这是唯一能自动守住「不重叠不溢出」的手段**;人眼验收留给 macOS 上真开一次 |
| 像素 → 预留行数 / 缩放 | ✅ 下沉纯函数 | 无 I/O,边界清楚(超高、超宽、极小图) |
| 前端 | ❌ | 解析放后端之后没有值得测的逻辑 |

### 必须存在的用例

护栏,防止后来者(包括 AI agent)把已经想清楚的事「优化」掉:

- 一张 1080 px 高的图片导出后,**下一个 Block 的起始行在图片下方**(守住「图片预留行而非撑行高」,撑行高的实现会在这里失败)
- 值为 `007` 的单元格读回来仍是字符串 `"007"`(守住 `@` 文本格式)
- 含制表符的单元格经 TSV 解析后不错位
- sheet 名 32 字符被录入接口拒绝(openpyxl 不会替我们拦)
- 删掉一个 image Block 后,它的文件不在磁盘上了(守住「Evidence 是引用计数规则的例外」)

## Out of Scope

刻意排除,不是遗漏:

| 项目 | 说明 |
| --- | --- |
| Evidence 搜索 | ADR-0001 把「靠搜索捞回」划给 Memo。真攒多了该加归档,不是搜索 |
| 表格加行 / 加列 | 数据来自 DB,手工加行意味着可以编数据 |
| 拖拽排序 | 上下移动 + 置顶置底够用,不值一个依赖 |
| 排版参数的配置文件 / 设置页 | 第一版集中在 dataclass 里 |
| 公司 Excel 模板 | 目前没有指定模板(requirements.md §3) |
| 压掉「以文本形式存储的数字」绿三角 | openpyxl 的 `IgnoredErrors` 没接到 worksheet 上,要拆 zip 改 XML |
| 导出后的状态 / 归档 | 没有 `exported_at`,没有已导出标记 |
| Log 作为独立 kind | 归进 `text`,不做特殊排版 |
| 导出文件名带时间戳 | 重复导出交给浏览器的 `(1)` 后缀 |

## Further Notes

### 这个里程碑不是「只加 Excel 导出」

design.md §8 原本把 M2 描述成「复用 M1 的图片链路,只加 Excel 导出」。实际它带进来三层模型、表格这一种全新的内容类型、以及前端路由。图片链路确实是复用的,但它只占其中一小块。

### 唯一在开发服务器上验不了的一条

粘贴 DB 结果这条路径需要**装了 IDEA 的机器**。TSV 解析本身有主接缝测试,但「IDEA 实际往剪贴板放了什么」只能在工作机或私人 macOS 上确认一次。其余(界面、存储、Excel 导出)在服务器上可以完整验证 —— 导出的 xlsx 下载到 macOS 用 Excel / Numbers 打开是 M2 的人眼验收。
