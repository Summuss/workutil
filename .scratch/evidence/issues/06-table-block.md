# 06: 表格 Block

**What to build:** 三种内容里最后也最麻烦的一种。从 IDEA 的 database 工具复制一段查询结果,粘进 Case 变成一张**保持行列结构**的表格。

**解析放后端。** 前端把剪贴板文本原样 POST,拿回 `rows` 和行列数。它是本模块边界矩阵最大的纯函数(引号、含制表符或换行的单元格、CRLF、各行列数不齐、结尾空行),放后端就落进既有的 HTTP 主接缝,不必为它破「前端不写自动化测试」;服务在 `127.0.0.1`,粘贴时多一次往返可以忽略。

**TSV 是主路径,`text/html` 是兼容。** 实测 IDEA 自带的 database 工具**只往剪贴板放 `text/plain`**,格式由结果集右上角的 data extractor 决定(DSV 家族默认 TSV);`text/html` 只在从网页或 Excel 复制时才有。

**`has_header` 不能靠猜。** IDEA 复制时带不带表头,取决于 Settings → Tools → CSV Formats → TSV 里的「First row is header」,工具这边无从判断第一行是列名还是数据。默认 `true`,UI 上一键可翻转。

存 `rows: string[][]`,**粘贴时解析定型,不存原始 TSV 事后再切** —— DB 的文本字段本身就可能含制表符,粘贴那一刻是唯一还知道单元格边界的时候。

**粘贴时的类型判别也在这张 ticket 收口**(它要三种 kind 都在场才做得了):有图片 flavor → image;`text/plain` 多行、含制表符、各行列数一致 → table;否则 → text。这个判别**一定会误判**(带缩进或对齐的日志长得像表格),所以生成后挂一条**可无视的确认提示**:「识别为表格,8 行 5 列 · 改为纯文字」。判对时零成本,判错时一次点击,而这条提示同时也是「刚才那一下确实进去了」的反馈。

**刻意不给加行加列。** 数据来自 DB,能手工加行就意味着 evidence 里可以出现编造的数据 —— 那正是 evidence 这个东西不该允许的事。
