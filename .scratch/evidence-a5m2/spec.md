# Spec: Evidence 导出对齐 a5m2,以及带换行的文字怎么落进 Excel

Status: ready-for-agent

## Problem Statement

**两个不相干但都发生在 evidence 上的问题。**

一、**工具导出的 evidence 和手工做的看起来不像同一批东西。** 既存的 evidence 全是把 A5:SQL Mk-2 的查询结果复制、粘贴进 Excel 手工做出来的;工具生成的那几份会和它们并排出现在同一批交付物里,而字体(Calibri vs 游ゴシック)、表头排版(截断 vs 换行)、NULL 的呈现(黑字 vs 灰字)都不一样。requirements.md §3 原本写着「自由格式,由工具自己定」,理由是「没有公司指定模板」—— 那句话只对了一半:**没有公司模板,不等于没有基准**。

二、**一段带换行的文字,导出后挤在一个单元格里。** 日志是逐行读的,挤成一格既难读也不像手工做的那份。

外加一件小事:**加完一段内容看不见它落在哪。** 新 Block 追加在列表末尾,而人常常正停在中间,加完屏幕上什么都没变。

## Solution

一、导出样式**以 a5m2 粘贴结果为基准**,对齐四项:字体、表头换行与垂直居中、NULL 灰色、(已有的)表头底色。详见 [ADR-0011](../../docs/adr/0011-excel-style-follows-a5m2.md)。

二、文字 Block 加一个 `split_lines` 开关(默认**逐行**),导出时决定是每行各占一个 Excel 行,还是整段挤进一格。

三、加完 Block 之后滚到它那里。**不加 toast** —— 病根是「看不见」,不是「没被告知」。

## Domain Model

不引入新概念。`split_lines` 是文字 Block 上的一个属性,和表格 Block 的 `has_header` 同类:**某个 kind 专属的一个布尔开关**,所以接口也长成同一个形状。

`CONTEXT.md` 不动。改的是 requirements.md §3 那条前提(已改)。

## User Stories

1. 作为使用者,我希望把工具导出的 sheet 和一份手工做的 evidence 并排放着,看不出是两个来源。
2. 作为使用者,我希望 `≪ NULL ≫` 在导出的 Excel 里是灰色的,和 a5m2 粘出来一样。
3. 作为使用者,我希望长列名在表头里**折行显示**而不是被截断 —— 列名是交付内容。
4. 作为使用者,我希望一段三行的日志导出后在 Excel 里占三行。
5. 作为使用者,我希望**某一段**可以单独选择「挤进一格」,而不是整份 evidence 一起变。
6. 作为使用者,我希望加完一段内容能看见它落在哪,不用自己往下翻找。

## Implementation Decisions

### 导出样式(ADR-0011)

- **字体 `游ゴシック` 11**,进 `LayoutSettings`(`font_name` / `font_size`)。此前是 openpyxl 默认的 Calibri。
- **表头 `wrap_text=True` + `vertical="center"`;数据行不设 alignment**(长值被右邻格截断、不折行)。这不只是「像」:`loop_kaiin_id` 在 18 宽的列里会被截断,而列名是交付内容。
- **值恰为 `≪ NULL ≫` 的单元格字体色 `#808080`**。精确匹配那一个字符串:U+226A + 空格 + `NULL` + 空格 + U+226B。**不 trim、不认 `«NULL»` 一类变体、不用正则** —— 数据里真实存在一个长得像 NULL 的字符串是可能的,而 evidence 的底线是「我看到的就是这个值」。**宁可漏判,不可错判。** 只作用于表格单元格,文字 Block 不参与。
- **判定在导出时按值做**,不在粘贴时打标记 —— 单元格可能被 `PUT .../cells/<row>/<column>` 改过。
- 字体、颜色、bold 全部经由 `layout.py` 的 **`_text_cell` 这一个漏斗**设置,`Font(...)` 的构造也收进去,调用方只传 bold / color。**不改 openpyxl 的 `Normal` 命名样式** —— 半私有 API,升级会静默变。
- **列宽 18 不动,这是明确的例外。** a5m2 粘贴根本不设列宽,Excel 里看到的是它自己的默认值(8.38 字符),这一项上没有对齐的对象;18 是为「同一 sheet 里图片和表格共存」定的。
- 表头底色 `#87e7ad`、细边框、`@` 文本格式**都不动**(前两个本来就是为对齐 a5m2 定的,第三个是 ADR-0004)。

### `split_lines`

- `evidence_block.split_lines: bool`,default `True`,一条迁移。
- 接口 `PUT .../blocks/<id>/split-lines`,**和 `has_header` 的 `PUT .../blocks/<id>/header` 同形** —— 同类东西该长一样,不塞进 `PATCH` 的正文里。
- 开关挂在 **Block 上而不是导出时**:它描述的是**内容是什么**(这段是逐行的日志 / 这段是一句说明),不是导出时的心情。一份 evidence 里两种文字同时存在是常态。
- 工具条上的开关**只在该 Block 含 `\n` 时显示** —— 不含换行时它没有任何含义。
- 导出:逐行时每行写一个单元格、占 `len(lines)` 行、**不设 `wrap_text`**(超长向右溢出比折成 20 行高的一格好读,也和「数据行不 wrap」一致);合并时仍是一格 + `wrap_text`,和现在一样。空行原样成为一个空 Excel 行(`"a\n\nb"` → 3 行)。Block 之间空一行的规则不变。
- **默认值改变了既有 Block 的导出结果**:老的文字 Block 迁移后拿到 `True`,重新导出会变成逐行。接受 —— 那正是想要的新行为,而 evidence 导出后使命即完成(ADR-0001),重导旧的极少见。

### 加完滚动

- `scrollIntoView({ block: "nearest" })` 滚到**最后一个**新 Block,三种 kind 都滚(一次粘 3 张图滚到第 3 张)。
- **不用 `smooth`** —— 连着粘几张图时动画会互相打断,在 §3.4 的滚动容器里看起来像卡顿。
- `block: "nearest"` 意味着已经在视野里时它本身就不动,不需要额外判断。
- **不加 toast。** 表格那条「识别为表格 · 改为纯文字」的既有提示不动 —— 它本来就兼着「刚才那一下确实进去了」的职责(design.md §6 F5),再叠一层只会把它盖住。

| 位置 | 测? | 理由 |

| 导出的 xlsx:字体 / 表头 alignment / NULL 颜色 | ✅ **主接缝** | 调导出接口拿 bytes,用 openpyxl 读回来断言。这是唯一能自动守住样式的手段 |

| `PUT .../split-lines` | ✅ 主接缝 | 对非文字 Block 应是 422 |
| 前端滚动与开关显隐 | ❌ | 沿用一贯做法,手动跑 |

## Further Notes

### 字体在 macOS 上会不一样,这是知情的

xlsx 里字体按**名字**存,渲染取决于打开它的机器。日文 Windows 一定有 `游ゴシック`;macOS 装的是 `YuGothic` / `游ゴシック体`,名字对不上时 Excel 自己回退。所以在 Mac 上预览和工作机上不一样 —— 交付对象在工作机那边,这个偏差只影响自己预览。不要为此加字体回退表,那会让「导出的到底长什么样」变成一个需要推理的问题。
