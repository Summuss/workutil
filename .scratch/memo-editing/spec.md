# Spec: Memo 的三处编辑手感

Status: ready-for-agent

## Problem Statement

三件每天都在硌手的小事:

1. **正文里打不出制表符。** 贴进来的东西经常要对齐,而 `Tab` 会把焦点弹走。
2. **开合只能够那个小箭头。** 卡片上大片区域点了没反应。
3. **折叠状态下想改一条要两步**:先展开,再去头部找「编辑」。

## Solution

1. `Tab` 在 memo 的两个输入框里插入一个真的 `\t`,`Esc` 作为键盘出口。
2. 点卡片**空白处**开合。
3. 折叠态多一个编辑按钮,一步展开并进入编辑态。

## Domain Model

不引入新概念,`CONTEXT.md` 不动。

## User Stories

1. 作为使用者,我希望在 memo 正文里按 `Tab` 打出制表符,并且**能用 `Ctrl+Z` 撤销**。
2. 作为使用者,我希望点卡片上的空白处就能展开或折叠,不必每次都瞄准那个箭头。
3. 作为使用者,我希望**拖选正文复制的时候什么都不发生** —— 这是这份 spec 的底线。
4. 作为使用者,我希望折叠状态下一步就能进编辑,并且存完还看得见自己刚存了什么。

## Implementation Decisions

### 这份 spec 真正的风险

**「拖选复制被当成一次点击」这个坑,项目已经踩过两次并回退过两次:**

- 一次是「点正文进编辑」(`.scratch/memo/issues/02` 底部「用了一天之后的回退」)
- 一次是「折叠态整行是 `<button>`」(`.scratch/memo/issues/08`)

**「点空白开合」是同一个坑的第三个入口。** 下面那两个条件不是防御性编程,是这份 spec 的全部要害。

### `Tab`

- 插入一个真的 `\t`,**替换选区**。不做多行缩进、不做 `Shift+Tab` 反缩进 —— memo 不是代码编辑器,多行缩进要处理选区扩展、行边界、撤销粒度,是另一个量级的功能。
- **用 `document.execCommand("insertText", false, "\t")`,不用 `setState`。** 后者会清空浏览器原生的撤销栈,`Ctrl+Z` 从此在这个框里失效 —— 而 memo 输入框是全项目打字最多的地方。`execCommand` 已被标记 deprecated,但它是保住撤销栈的唯一办法;返回 `false` 时退回 `setState`。
- 键盘出口:编辑态维持 `Esc`(退出编辑、保留草稿)的既有语义;**`MemoComposer` 里 `Esc` = `blur()`,不清空内容** —— 它现在没有任何退出键,Tab 被吃掉之后键盘用户会被困在里面。
- **只作用于 memo 的两个输入框。** evidence 的 `BlockTextArea` 明确不动:制表符是它判断「这段粘贴是不是表格」的判据(design.md §6 F5),手打的 Tab 会污染那道粗筛。

### 点空白开合

判定**必须同时满足两个条件**:

1. **点击目标属于一张白名单容器** —— 卡片本体(`li.card`)、折叠行的 flex 容器、展开态的头部行、正文外层 div。
2. **`window.getSelection().isCollapsed`** —— 这一下没有留下选区。

**白名单是刻意的,不是偷懒。** 渲染出来的正文是一串块级 `<p>`,**一段短句子右边那片看起来是空白的地方,DOM 上仍然是那个 `<p>`**。把 `<p>` 也算进空白,单击一个词就会折叠 —— 而双击选词的第一下就是单击。代价是「段落右侧点不动」,接受。

不用 `caretRangeFromPoint` 一类的启发式去猜「这一下在不在字上」:`.scratch/memo/issues/08` 立过「不新发明一套启发式判断」的规矩,而那种判断在不同浏览器上不一致。

其他边界:

- **编辑态不响应** —— 点空白就把草稿卷起来是拿数据换一次点击。
- **`SingleMemoPage` 不参与** —— 它恒为展开,没有折叠态。
- 折叠态可点的空白是「文字与图标区之间的间隙」(那段属于 `justify-between` 的父容器)加卡片 padding;展开态是卡片边缘与正文下方。

### 折叠态编辑按钮

- 折叠态图标区现在是「置顶 + 展开」,加进编辑变三个。点它 = 展开 + 直接进编辑态,光标落末尾。
- **保存后留在展开态**,和从展开态进入编辑一致 —— 自动折叠会让人看不到自己刚存了什么。
- 这条不违反「编辑由按钮进入,不由点正文进入」:进编辑的仍然是**按钮**。

## Testing Decisions

| 位置 | 测? | 理由 |
| --- | --- | --- |
| 前端交互 | ❌ 自动化 | 沿用一贯做法(design.md §4 测试接缝)。唯一的前端自动化测试是 Markdown 的 raw HTML 守卫,那是安全线,这里不是 |
| 手动 | ✅ **重点** | running.md 里「Memo 编辑手感(M7)」整节,尤其**拖选复制不触发开合**、**双击选词不折叠**、**`Tab` 后 `Ctrl+Z` 能撤销**三条 |

后端**零改动** —— 这份 spec 不碰任何接口。改了就说明走错路了。

## Out of Scope

| 项目 | 说明 |
| --- | --- |
| 多行缩进 / `Shift+Tab` 反缩进 | memo 不是代码编辑器 |
| evidence 输入框的 `Tab` | 制表符是它的表格判据,刻意不做 |
| 段落右侧那片视觉空白 | DOM 上属于 `<p>`,算进去就等于「单击一个词就折叠」 |
| 编辑态下点空白折叠 | 拿草稿冒险 |
| `SingleMemoPage` 的点空白 | 它没有折叠态 |
| 所见即所得编辑器 | 一直不做,理由见 design.md §6 F1 |

## Further Notes

### `execCommand` 是 deprecated,为什么还用它

在 `<textarea>` 里插入文本并保住浏览器原生撤销栈,今天没有第二个办法 —— `Input Events Level 2` 的 `beforeinput` + `insertText` 在 textarea 上并不能替代它,而自建撤销栈意味着要重新实现光标、选区、合并粒度这一整套。所有主流浏览器仍然支持 `execCommand("insertText")`,且没有移除时间表。真被移除那天,`setState` 的退路已经在代码里了 —— 那时坏掉的是撤销,不是输入。
