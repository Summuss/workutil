# 05: 失效检测

**What to build:** 一个**单独的**检查接口,把「这条书签指向的东西还在不在」告诉前端。

**它不在列表接口里做,这一条是本 ticket 的全部理由。** design.md 早先那句「列表加载时批量 `os.path.exists`,不阻塞渲染」是自相矛盾的:在列表接口里做它就**是**阻塞的。而 Windows 上一条指向已断开网络驱动器的路径,`os.path.exists` 能卡好几秒 —— 整个书签页跟着卡,而书签页恰恰是「重启之后第一个打开的东西」。

所以:**列表先渲染,检查另起一个请求,结果回来再打灰标。**

**结果回来之前显示「未知」,不是「有效」。** 不给一个还没验证过的东西盖绿章 —— 三态(未知 / 有效 / 失效)在 UI 上要能分辨,哪怕「未知」只存在半秒。

不设超时(`os.path.exists` 也没法设)。慢就慢在那个单独的请求里,页面已经能用了。
