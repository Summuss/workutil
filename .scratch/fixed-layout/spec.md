# Spec: 界面外壳固定一屏,内容区各自滚动

Status: ready-for-agent

## Problem Statement

每个画面的可视区域都会**随内容伸缩**,用起来晃眼:

- 展开一条带截图的 Memo,卡片高度暴涨(图片按 `max-width:100%; height:auto` 渲染,一张 1920 宽的截图在 768px 容器里能占几百像素高);折叠回去又缩回一行。整页高度跟着跳,滚动条长度跟着变。
- Evidence 切换用例时,内容区先塌成一行 loading 占位、再撑到新用例的高度 —— 一次切换看到两跳。
- 书签页「打开了 5 个,跳过 2 个」这类提示条插在内容流里,出现时把下面所有东西推下去。
- 各页宽度还不统一:Memo 是 `max-w-3xl`(768px),Todo / Bookmark / Evidence 是 `max-w-2xl`(672px),切页时连内容宽度都在跳。

根子在外壳:`App.tsx` 用的是 `min-h-screen flex-col`,`<main>` 高度完全跟着内容走,滚动的是整个窗口。

## Solution

**外壳固定为一屏高,滚动下放到每页的内容区。** `App.tsx` 从 `min-h-screen` 改为 `h-dvh overflow-hidden`,导航条保持 52px 不参与滚动,`<main>` 变成 `flex-1 min-h-0` 的滚动容器。每页再在内部划一条线:高频操作的输入区钉住不动,列表部分滚。

在这个前提上补三件治标的事,因为固定外壳单独治不了它们:

1. **Memo 里的图片改为高度上限 200px 的缩略图**,点击开灯箱看原图 —— 否则一条 memo 仍能自己吃掉两屏。
2. **Evidence 用例内容区用等高骨架占位**代替会塌陷的 loading 文字;切换用例时滚动位置回到顶部。
3. **书签页的提示条改为浮在内容区顶部的覆盖层**,不占布局高度。

四页宽度统一到 **768px**(`max-w-3xl`)。

## Domain Model

不引入新领域概念,`CONTEXT.md` 不动。这是一次纯粹的呈现层改造:没有任何一个概念的含义、生命周期或关系发生变化。

## User Stories

1. 作为使用者,我希望展开一条带截图的 Memo 时,页面框架不动 —— 不出现整窗滚动条突然变长、其他 memo 被推到屏幕外的跳动。
2. 作为使用者,我希望在 Evidence 里来回切换用例时,内容区始终是同一块矩形,不会先塌陷再撑开。
3. 作为使用者,我希望在 Memo 页往下翻很久之后,输入框和搜索框仍然在原地,不用滚回顶部才能记下一条。
4. 作为使用者,我希望在 Evidence 里连续粘贴多张截图时,粘贴框始终可见,不需要每贴一张就滚到底部找它。
5. 作为使用者,我希望「打开了 5 个,跳过 2 个」这类提示出现时,书签列表不会整体往下挪。
6. 作为使用者,我希望在 Memo 里点一张截图能看到原图全貌,按 `Esc` 或点背景就关掉。
7. 作为使用者,我希望在导航里切换功能时,内容的左右边界在同一个位置,不会一页宽一页窄。

## Implementation Decisions

### 外壳

- `App.tsx`:`min-h-screen` → `h-dvh overflow-hidden`。用 `dvh` 而不是 `vh`,桌面上二者等价,但 `dvh` 不会在任何带动态工具栏的环境里溢出。
- 每页 `<main>` 从 `mx-auto flex max-w-2xl flex-col gap-* px-8 py-9` 改成「外层撑满 + 内层限宽」两层:外层负责 `flex-1 min-h-0` 和滚动,内层负责 `mx-auto max-w-3xl` 和内边距。
- **`min-h-0` 是这次改造最容易踩的坑**:flex 子项的 `min-height` 默认是 `auto`,内容会把它撑破容器、滚动条又长回到窗口上。每一个「要滚的 flex 子项」都必须显式 `min-h-0`。
- 不加响应式断点。两台目标机器都是桌面浏览器全屏使用(requirements.md §2),窄窗口不在这次范围内。

### 每页的固定区 / 滚动区

| 页面 | 钉在顶部 | 滚动区 | 钉在底部 |
| --- | --- | --- | --- |
| Memo(`/`) | 输入框 + 搜索栏 | memo 列表 | — |
| Memo 详情(`/memo/:id`) | 返回行 | 正文 | — |
| Todo(`/todos`) | 新增输入框 | todo 列表 | — |
| Bookmark(`/bookmarks`) | 「登记书签 / 新建分组」按钮行 | 分组与散装列表 | — |
| Evidence 列表(`/evidence`) | 新建按钮行 | evidence 列表 | — |
| Evidence 详情(`/evidence/:id`) | 返回/标题/导出行 + 用例标签栏 | block 列表 | 新增 block 的输入框 |

- Evidence 详情的**新增 block 输入框钉在底部**,而不是跟着列表滚到末尾。理由是 requirements.md §4 F5 那条验收要点:「连续粘贴多张截图,过程中不需要切换到其他软件」—— 输入框常驻,粘完新块出现在它上方。代价是它和「追加到末尾」的空间语义脱了钩,接受。
- 展开的 Memo 卡片**不设高度上限、不做内部滚动**。页面滚动条里套卡片滚动条会带来滚轮边界穿透,体感比现在更糟;高度问题由下面的缩略图解决。

### Memo 图片:缩略图 + 灯箱

- 缩略图:**高度上限 200px,等比缩小完整显示**(不裁剪),宽度自适应;原图比 200px 矮就原样显示,不放大。在 `.markdown-body img` 上改。
- 点击缩略图 → 全屏半透明遮罩,图片按窗口尺寸完整显示,**不放大超过原始尺寸**。
- 关闭:`Esc`、点遮罩背景、右上角关闭按钮,三种都要。
- **不做多图左右切换**。一条 memo 里的几张图彼此无关,翻页要引入「当前第几张」的状态,是多余的心智负担。
- 灯箱是 `shared/` 下的自建组件,不引第三方依赖,样式沿用 `ConvertToTodoModal` 的遮罩做法(`var(--scrim)` + `fixed inset-0 z-50`)。
- **`Esc` 必须挂 document 级监听**,不能照抄 `ConvertToTodoModal` 那个挂在遮罩 div 上的 `onKeyDown`:那里能work是因为焦点落在模态内的 input 上,而灯箱里没有可聚焦元素,键盘事件根本不会冒泡到那个 div。
- `MemoPage` 的列表和 `SingleMemoPage` 用**同一套**渲染(改 `MemoMarkdown` 一处即可),不做例外。
- Evidence 的图片 Block **保持原样**(整张显示)。那里是在核对要交付出去的内容,看得清比排得整齐重要 —— `BlockCard.tsx` 里那条「Shown whole」的注释继续成立。

### Evidence 内容区

- `CaseBlocks` 的 loading 分支从「一行居中文字」换成**与内容区等高的骨架占位**,加载中不改变布局高度。
- `key={selectedId}` 的重挂载保持不变(它保证的是「不会看到上一个用例的内容」),但滚动容器在切换后**回到顶部**。
- 不缓存已加载过的用例内容。缓存会带来「别处改了这个用例、切回来看到旧的」的一致性问题,收益不值。

### 书签页提示条

- `notice` 与 `error` 从内容流里挪出来,改为**绝对定位浮在滚动区顶部**,不占布局高度,有关闭按钮(已有)。
- 只改书签页。其他页的错误提示都是单行文字、位置固定,不会造成可见的跳动。

## Testing Decisions

| 位置 | 测? | 理由 |
| --- | --- | --- |
| 布局 / 滚动 / 灯箱 | ❌ | 全部是 UI 交互,沿用本仓库一贯做法,手动跑 `/run` 验证 |
| 后端 | — | 这个 spec 不碰后端 |

`docs/running.md` 的手动清单要补:外壳不跳动、灯箱开关、Evidence 切用例不塌陷、书签提示条不推挤、四页宽度一致。

## Out of Scope

| 项目 | 说明 |
| --- | --- |
| 响应式 / 窄窗口 / 移动端 | 目标机器是桌面浏览器全屏,不做断点 |
| 展开的 Memo 卡片内部滚动 | 嵌套滚动的体感比现在更糟,用缩略图解决高度问题 |
| 灯箱的多图导航、缩放、旋转 | 看一眼原图就够,不做看图软件 |
| Evidence 图片块改缩略图 | 交付前的核对场景,整张显示是刻意的 |
| 记住每个用例的滚动位置 | 一个用例通常只有几屏,「切过去看到开头」更可预期 |
| 深色模式 / 主题 | 与本次无关 |

## Further Notes

### 这是一个会动到每一个页面文件的改动

七个页面组件全部要改外壳结构,所以它排在其他三个 spec 之前做 —— 否则后面每个 spec 都要在改完的页面上再改一次。

### 与 ADR 的关系

「放弃浏览器原生滚动」是一个难以逆转、且未来读者一定会问「为什么不让页面自然变长」的决定,记在 `docs/adr/0007-fixed-viewport-shell.md`。

### 对拖拽的影响(下一个 spec 的前提)

内容区变成 `overflow` 滚动容器之后,**现有的拖拽会在容器边缘被裁剪** —— dnd-kit 现在是「原地半透明 + transform 位移」,没有浮层。本 spec 不修它(同容器内拖拽的位移幅度小,裁剪不明显),但 `bookmark-cross-group-drag` 必须引入 `DragOverlay`,那里跨容器是必然的。
