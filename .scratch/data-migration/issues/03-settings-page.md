# 03: `/settings` 页与导航入口

**What to build:** 新路由 `/settings`、`features/settings/` 目录、导航栏右侧一个齿轮图标,以及页面上的导出 / 导入两个操作。

**为什么单开一页而不是往语言切换旁边挂个菜单:** 以后一定还会有别的设置(导出参数、数据目录位置),而「新增一个功能不应改动既有功能」是第一约束(requirements.md §5)。一个页面比一个下拉菜单经得起加东西。

**语言切换留在导航栏,不搬进来。** 切语言是**当场就要看到效果**的动作,而且是唯一一个在任何页面上都可能想改的偏好;`/settings` 装的是「一次性的、要专门去做的」事。design.md §6 F6 里那句「不新建 Settings 页面」的理由已随本票失效,文档已同步。

**页面内容:**

- **导出数据**:一个按钮,触发下载。导出可能要几秒(几百 MB 的 images),按钮要有进行中的状态,不能让人以为没点上。
- **导入数据**:选文件 + 一个确认。成功后**明确显示「请关掉 workutil 再重新打开」** —— 不重启看到的还是旧状态,这一句不能只是小字。
- 票 02 的四种拒绝各自显示自己的提示,不要统一成一句「导入失败」:「已经有数据了」和「版本不匹配」的下一步动作完全不同。

**布局遵守固定外壳(design.md §3.4)**:`/settings` 也是一个 `flex-1 min-h-0` 的滚动容器,内容宽度 `max-w-3xl`,和其余四页一致。
