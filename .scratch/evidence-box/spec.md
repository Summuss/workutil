# 在截图上画红框

## 起因

做 evidence 时,有些截图要标出**点的是哪个按钮、要确认的是哪一处**。现在的做法是在 Excel 里插一个四边形,去掉填充、边框改成红色,压在截图上。

工具导出的 Excel 里没有这一步,于是只剩两条路,都不好:

- **导出之后再到 Excel 里手工框。** 每导出一次就要重框一次 —— 而导出不是一次性的,改一张图、调一下顺序都要重导。
- **先用别的软件框好再贴进来。** 框就烧进了截图,框错了回不去,原图也没了。

## 定下来的

### 红框是图片 Block 上的数据,不是图片的一部分

- image Block 多一个 `boxes`:一组矩形 `{x, y, w, h}`,单位是**原图像素**,整数。
- **原图一个字节不动**(design.md §5)。框是叠在图上画出来的,导出时变成 Excel 里的四边形。所以框随时能删、能改,不需要另留一份原图。
- 坐标用原图像素,因为原图永远不变(文件名一次性,design.md §5);卡片、灯箱、Excel 各自把图缩成多大,都不影响框落在哪。
- 复制用例时,框跟着一起复制。

### 在灯箱里画

卡片上的图缩进了一屏(evidence-case-browsing/01),长截图是窄窄一条,在上面画不准。灯箱按宽度铺满、字看得清 —— 画框在那里。

- **入口**:image Block 工具条上一颗「框选」,点了直接打开灯箱并进入框选模式。evidence 的灯箱里也有同一个开关。memo 的灯箱不接。
- **画**:框选模式下在图上拖一下,就是一个框。拖得太短(几个像素以内)不算 —— 否则点一下就多出一个看不见的框。拖出图外的部分截到图的边上。
- **改**:点一个框选中它,`Delete` / `Backspace` 删掉;`Ctrl+Z` 撤销上一步(画或删)。**不做拖动改位置、拉角改大小** —— 删掉重画一样快,用下来不够再加。
- **每一步立刻保存**,整组提交。**不走草稿那一套**(CONTEXT.md「草稿」):草稿防的是「写到一半」,而一个框画完就是完整的,没有半个框。保存失败就退回服务器上的样子,并且说一声。
- `←` `→` 照常在本用例的截图之间翻,框选模式保持 —— 一个用例里要框的几张图可以一口气框完。
- `Esc` 关灯箱。

### 在哪里看得到

卡片、灯箱、大纲的缩略图上都叠着框。看见框才知道这张图框过了、框在哪,而不必等导出。

屏幕上的线宽是固定像素,不跟着图缩小 —— 否则长截图缩成窄条之后,框细到看不见。

### 导出:Excel 里能拖的四边形

- 每个框导出成一个 **Excel 原生的四边形**:无填充、红色 `FF0000`、线宽 2.25pt。颜色和线宽进 `LayoutSettings`。
- **为什么不把框画进导出的图片里**(实现起来只要几行 Pillow):交付之后,框要能在 Excel 里点中、拖动、删除 —— 和手工做的那些 evidence 一样。这是明确的要求。
- **openpyxl 写不出形状。** 它的 drawing 模型只认图片和图表:`SpreadsheetDrawing._write` 只遍历 `charts + images`,`GroupShape` 也只装得下一张 `pic`(openpyxl 3.1.5 实读源码)。做法是 `wb.save` 之后,改写 xlsx 里的 `xl/drawings/drawingN.xml`,把四边形补进去。
- 截图本身怎么导出(缩小副本、预留行)一行不动。

### 推翻了什么

ADR-0004 在绿色三角那里说过「压掉它要拆 xlsx 的 zip 手改 XML,不值得」。那句话的意思是,为了一个小三角付这个代价划不来;它并不是一条「永远不改 XML」的规矩。这一次,能拖动的框就是用户要的交付形态,openpyxl 之外也没有别的路可走,所以这个代价要付。会留一条 ADR 记下来。

## 待验证:框和截图怎么摆,在 Excel 里才不会错位

截图是用 `oneCellAnchor` 钉在 `A` 列某一行上的,大小是绝对值(EMU),不依赖列宽。框可以用两种方式摆上去:

| | A:跟截图编成一组 | B:每个框单独摆 |
| --- | --- | --- |
| 怎么定位 | 框用**组内坐标**,也就是截图自己的坐标系,不经过任何行高和列宽 | 行:`row + y ÷ 20px`,这一步是精确的,预留行都显式写成了 20px。列:钉在 `A` 列,`colOff = x`,偏移可以比 `A` 列还宽 |
| 错位风险 | 格式上就不会错位 | 取决于 Excel 认不认「比单元格还宽的偏移」。如果 Excel 把偏移截断到单元格宽,框就全挤到左边 |
| 在 Excel 里拖 | 点第一下选中整组,再点一下选中某个框,然后就能拖、能删;也可以先「グループ解除」 | 和手工画的一样,点一下就能拖 |
| 拖动截图 | 框跟着一起动 | 截图动了,框留在原地 |

**不考虑**「按列宽把 x 拆成第几列 + 列内偏移」:列宽在 Excel 里换算成像素要用默认字体的数字宽度,而这个宽度会随 Windows 的显示缩放变化。这和「预留行在 125% 缩放下变矮」(design.md §6 F5)是同一类坑,而且列宽没有 `customHeight` 那样的办法可以钉死。

**验证材料**:分支 `prototype/evidence-annotation-shapes` 上的 `backend/app/modules/evidence/PROTOTYPE_shape_export.py`。它用真的 `build_evidence_workbook` 生成一份 xlsx,里面两个 sheet(`A_group` / `B_separate`),内容相同,共三张图:一张宽图(会被缩小)、一张长图(127 个预留行)、一张小图(1:1 放进去)。每个目标位置在截图里都画了一圈**蓝色细线**:红框正好压住蓝线就是对齐了,红框旁边还能看到蓝线就是错位了。

要在工作机(Windows,实际用的显示缩放)和 Mac 上分别看:

1. 打开时 Excel 有没有弹「修复」。弹了说明注入的 XML 有问题。
2. 两个 sheet 里每个红框是否压住它的蓝线,尤其是宽图右边的 T2、长图右下角的 T3,误差最容易在这两个位置显出来。
3. 把 Excel 的缩放调到 75% / 150%,看框和图是否还对得上。
4. 拖一个框、删一个框,看手感怎么样。

结论决定 03 的做法:B 在两边都对得上,就用 B(和手工的一样);对不上就用 A。

## 不做

| 项目 | 说明 |
| --- | --- |
| 箭头、文字、圆圈 | 只要了红框。先把这一样做顺手 |
| 在工具里换颜色、换线宽 | 是 `LayoutSettings` 里的一个值,不做成界面 |
| 拖动改位置、拉角改大小 | 删掉重画一样快。用下来不够再加 |
| 在卡片上直接画 | 卡片上的图缩过,画不准 |
| memo 里的图画框 | 框是给交付物用的,memo 不导出 |
| 把框画进导出的图片 | 交付后要在 Excel 里能拖,见上 |
