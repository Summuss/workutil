# 01: 在灯箱里画红框,卡片、灯箱、大纲上看得到

**Status:** resolved

**Blocked by:** 无

**What to build:** image Block 能带一组红框。在 evidence 灯箱的框选模式里拖一下就画出一个框,马上存下来;卡片、灯箱、大纲的缩略图上都能看到。为什么这样做见 [spec](../spec.md)。

### 后端

- `EvidenceBlock` 加一列 `boxes`:JSON,默认 `[]`,每一项是 `{x, y, w, h}`,单位是原图像素,整数。写 Alembic 迁移,已有的行都是 `[]`。和 `rows` 一样,**每次写入都赋一个新 list**,模型里那段注释说过,JSON 列是按身份追踪的。
- Block 响应带上 `boxes`,非 image Block 恒为 `[]`。
- `PUT .../blocks/<id>/boxes`,请求体是 `{"boxes": [...]}`,**整组替换**。它和 `/label`、`/header`、`/split-lines` 同形:都是某种 kind 专属的一项属性,同类的东西接口长一样(design.md §6 F5)。
  - 非 image Block:422。
  - `w`、`h` ≥ 1;`x`、`y` ≥ 0;`x + w`、`y + h` 不超出原图。尺寸由服务端读原图得到,PIL 只读文件头。超出就 422。截到图边是前端的事,服务端只负责拒绝。
- `duplicate_case` 要显式复制 `boxes`。它是一个字段一个字段抄的,漏抄的话,复制出来的用例上的框会静静地消失。
- 测试走 HTTP 主接缝:PUT 之后 GET 回来一致;越界返回 422;对文字 Block 返回 422;复制用例后框一致,改副本的框不影响原用例;空数组表示清空。

### 前端

- 一个 `BoxOverlay`:一层绝对定位的 SVG 叠在 `<img>` 上,`viewBox` 设成原图尺寸(`naturalWidth/Height`),框按原图坐标画,图缩放时它跟着一起缩。线宽用 `vector-effect: non-scaling-stroke` 固定像素,卡片和灯箱上是 2px,大纲缩略图上是 1px。颜色和导出一样是红色。
- 卡片(`BlockCard`)、灯箱、大纲缩略图(`BlockOutlineRow`)三处都接 `BoxOverlay`。卡片上的图片在 `<img>` 外面要包一层 `relative inline-block`,包的时候注意 evidence-case-browsing/01 的高度上限(`100cqh`)不能失效。
- **框选模式**:`shared/Lightbox` 加**可选**的 props,不传就和现在完全一样,memo 就是不传的那一方。
  - image Block 工具条上加一颗「框选」,点了打开灯箱,直接进入框选模式。灯箱里有一个开关,框选模式下高亮。
  - 在图上按下、拖动、松开,就生成一个框。拖动过程中实时画出来。松开时宽或高不到 5 个**屏幕像素**的,不算。
  - 指针位置换算成原图坐标:`(clientX − rect.left) × naturalWidth ÷ rect.width`,再截到 `[0, naturalWidth]` 之内,纵向同理。
  - 每画一个框就 PUT 一次整组。失败了退回 PUT 之前的那组,并给一句提示。
  - `←` `→` 照常翻,框选模式保持。
  - 框选模式下,**在图上按下、在遮罩上松开,不能关掉灯箱**。按下和松开落在不同元素上时,`click` 会落在它们共同的祖先上,这正好可能是遮罩。框选模式下,点遮罩关闭这个行为可以整个关掉,反正还有 `Esc` 和 ✕。
  - 框选模式下,在图上拖动不能触发浏览器原生的图片拖拽(`draggable={false}` / `preventDefault`)。
- 新文案出中日两份。
