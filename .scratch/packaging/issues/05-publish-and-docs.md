# 05: 发布渠道与文档

**What to build:** 把包送到工作机的那条路,以及所有需要跟着改的文档。

工作机**能匿名访问 GitHub 但不能登录账号**,所以渠道是 GitHub Release 的 zip 资产 —— 这要求**仓库是 public**。仓库目前**没有任何 remote**,代码只在开发服务器上,所以这一步是「建仓库 + 推 + 发 release」,不是「加个 workflow」。

> ⚠️ **公开仓库需要单独确认后才能执行。** 已扫过内容:没有邮箱、密钥或公司标识;唯一的真实标识是 `docs/running.md` 里的 `summus@192.168.3.3`(私有网段,出了局域网没有意义,但应改成占位符)。除此之外 `.scratch/` 里的 spec 和 `docs/` 里的中文文档会一并公开,内容是这个工具本身的设计推导,不涉及雇主信息。**没拿到确认之前不要 push。**

文档这边,`requirements.md §6` 那条「工作机能否自由安装软件」现在可以关掉了 —— 实测结论是**工作机可以在任意位置执行程序**,而便携包本来也绕开了「安装」。
