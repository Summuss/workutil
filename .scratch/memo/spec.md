# Spec: Memo(M1)

Status: ready-for-agent

## Problem Statement

开发过程中不断产生琐碎信息 —— 一段报错堆栈、一条能复现问题的命令、测试环境的临时凭据、同事口头交代的注意事项。我现在把它们记在记事本里。

随着累积,记事本变成一堆无法管理的文本:三个月后想找回「上次那个超时问题当时是怎么绕过去的」,只能靠肉眼翻。更麻烦的是,**有相当一部分信息本身是图像** —— 报错截图、界面状态截图 —— 记事本根本存不下,只能另存成散落各处的图片文件,和对应的文字彻底脱节。

结果是:记录这个动作本身很轻,但记录下来的东西几乎没有被再次用到过。

## Solution

一个打开即可写的单页界面。

打开工具时**光标已经在输入框里**,不需要任何导航点击。打字,或者直接 `Ctrl+V` 把剪贴板里的截图粘进来 —— 图片就落在光标位置,和它要说明的那段文字挨着。`Ctrl+Enter` 保存,新记录立刻出现在下方的时间倒序列表里,输入框清空,可以接着记下一条。

要找回时输入关键词,结果**直接显示命中的那一段文字**,而不是只显示开头让你猜为什么这条会出现。中文和日文的两字词(バグ、対応、中文)都能搜到。

## User Stories

### 录入

1. 作为开发者,我希望打开工具时光标已经在输入框里,这样我不需要任何点击就能开始记录。
2. 作为开发者,我希望输入文字后按 `Ctrl+Enter` 就能保存,这样我的手不需要离开键盘。
3. 作为开发者,我希望保存后新记录立刻出现在列表顶部,这样我能确认它确实被存下来了。
4. 作为开发者,我希望保存后输入框自动清空并保持聚焦,这样我可以连续记录多条而不必重新点击。
5. 作为开发者,我希望把剪贴板里的截图直接 `Ctrl+V` 粘进正文,这样我不需要先存成文件再上传。
6. 作为开发者,我希望粘贴的图片出现在**光标当前位置**,这样图片和说明它的文字保持相邻。
7. 作为开发者,我希望在一条 Memo 里粘贴多张图片,这样我能记录一个有多个画面的问题。
8. 作为开发者,我希望也能把图片文件拖拽进输入框,这样来源不是剪贴板时同样方便。
9. 作为开发者,我希望正文支持 Markdown 的代码块,这样报错堆栈和命令行能以等宽字体清晰呈现。
10. 作为开发者,我希望代码块有语法高亮,这样长报错更容易扫读。
11. 作为开发者,我希望编辑区就是一个纯文本框而不是富文本编辑器,这样粘贴行为可预期、不会带进奇怪的格式。
12. 作为开发者,我希望一次保存就产生一条 Memo,粒度由我当场决定,这样工具不会强迫我把一件事拆成三条。

### 浏览

13. 作为开发者,我希望列表按**创建时间**倒序,这样最近记的东西在最上面。
14. 作为开发者,我希望列表里每条只显示正文首行,这样一屏能看到更多条。
15. 作为开发者,我希望含图片的 Memo 在列表里有「含 N 张图」的标记,这样我知道点开会有图。
16. 作为开发者,我希望列表加载时**不下载图片原图**,这样即使我存了几百张截图,列表依然秒开。
17. 作为开发者,我希望点开某条 Memo 才加载它的图片,这样流量花在我真正要看的东西上。
18. 作为开发者,我希望展开后能看到渲染后的 Markdown 和内联的图片,这样内容以我写的时候设想的样子呈现。

### 编辑与删除

19. 作为开发者,我希望通过卡片上的展开按钮就地展开,这样首行文字可以自由拖选复制,且不需要经过「查看页 → 点编辑」两次跳转。
20. 作为开发者,我希望能修改已保存的 Memo,这样信息过期时(比如 token 换了)我可以更新它。
21. 作为开发者,我希望修改一条旧 Memo **不会把它顶到列表最上面**,这样「我大概是上个月记的」这个定位方式依然有效。
22. 作为开发者,我希望能向已有的 Memo 里追加新的图片,这样后续补充的截图能和原文放在一起。
23. 作为开发者,我希望能删除 Memo,这样过时和无用的记录不会一直占据列表。
24. 作为开发者,我希望删除 Memo 时它的图片文件被一并清理,这样磁盘上不会堆积无人引用的截图。

### 搜索

25. 作为开发者,我希望输入关键词搜索所有 Memo 的正文,这样我能找回几个月前记的东西。
26. 作为开发者,我希望搜索能匹配正文的**任意位置**而不只是开头,这样关键词出现在第五行的记录也能被找到。
27. 作为开发者,我希望搜索结果显示**命中的那段文字**并高亮关键词,这样我一眼就能判断这条是不是我要找的。
28. 作为开发者,我希望搜索中文和日文的**两字词**(如「中文」「バグ」「対応」)能正常命中,这样我用母语记录的内容同样可以找回。
29. 作为开发者,我希望一条 Memo 里多处命中时都能看到,这样我不会因为只看到第一处而误判。
30. 作为开发者,我希望搜索无结果时有明确提示,这样我知道是真的没有,而不是工具坏了。
31. 作为开发者,我希望清空搜索框就回到完整的时间倒序列表,这样退出搜索不需要额外操作。

### 数据与安全

32. 作为开发者,我希望关掉工具再打开,所有 Memo 都还在,这样我敢把重要信息记进来。
33. 作为开发者,我希望把整个数据目录拷贝走就是一份完整备份,这样我不依赖工具提供导出功能也能自保。
34. 作为开发者,我希望服务只监听本机,这样局域网里的其他人无法访问我的记录。
35. 作为开发者,我希望从网页或 Slack 复制来的内容即使含有 HTML 或脚本也**不会被执行**,这样粘贴动作本身是安全的。

## Implementation Decisions

### 范围与定位

- 这是本项目的**第一个模块**,因此它同时承担立起项目骨架的职责:后端应用入口、数据库初始化与迁移、模块注册方式、前端应用外壳、开发与构建脚本。骨架不单独作为一个阶段,而是作为让第一条 Memo 端到端跑通所必需的部分被带出来。
- 后续四个功能(Evidence、书签、Todo、脚本)将照抄本模块确立的结构,因此模块内部的文件职责划分要在这里定型。

### 领域模型

- **Memo** 的字段:标识、正文、创建时间、修改时间。
- **没有标题字段**。列表中显示的「标题」是正文首行,由展示层截取,不是存储的字段。
- **没有标签字段**。归类能力不在第一版范围内。
- 正文存储的是 **Markdown 原文**,渲染发生在前端。
- 列表排序使用**创建时间**。修改时间要存储(用于展示「已修改」之类的信息),但**不参与排序**。
- Memo 与 Evidence 是两个独立概念,本模块不为将来的 Evidence 预留任何共用抽象;两者只共享图片存储机制(见 ADR-0001)。

### 搜索

- 使用 **子串匹配**,不使用 FTS5。理由与实测数据见 ADR-0002 —— FTS5 的两种分词器对中日文两字词均失效。
- 搜索结果对每条命中返回:正文首行,加上**命中片段**(关键词前后各截取若干字符)与命中位置,供前端高亮。
- 片段提取是一个**纯函数**:输入正文与查询词,输出片段列表。它不接触数据库和文件系统。
- 片段提取需要处理:中日文按字符截断与英文按词边界截断的差异、一条正文中的多处命中、命中位于正文开头或结尾、关键词横跨截断边界。

### 图片

- 图片通过浏览器的 **paste 事件**取得,而非由后端读取系统剪贴板 —— 这样跨平台行为一致,且不受服务运行在哪台机器影响。
- **保存是原子的**:编辑期间图片仅以 Blob 形式存在于浏览器内存中,正文里先使用临时引用;`Ctrl+Enter` 时正文与所有新图片在**同一个请求**内提交,后端在该请求中落盘并把临时引用改写为最终引用。
  - 这样就不存在「图片已上传但 Memo 尚未创建」的中间态,因而不需要暂存区、不需要草稿记录、不需要孤儿清理任务。
  - 代价:编辑期间浏览器崩溃会丢失尚未保存的内容。对于「随手记」这个场景可以接受。
- 图片按所属 Memo **分目录存放**。删除一条 Memo 即删除它的整个图片目录。
- **不做引用计数**。从正文中删掉某张图的引用**不删除文件**。理由见 design.md:引用计数需解析正文,而剪切文字的中间态引用数为 0,会造成不可逆的误删;留下无人引用的文件是可逆且无害的。
- **原图存储,不压缩、不生成缩略图**。图片存储机制由 Memo 与 Evidence 共享,而 Evidence 的截图要交付进 Excel,画质一旦压掉无法找回。

### 接口契约

- 列表接口**不返回图片内容或图片 URL 列表**,只返回图片**数量**。图片仅在展开单条 Memo 时随详情返回。这是让列表在积累数百张截图后依然秒开的关键。
- 搜索是列表接口的一种参数化形式(带查询词),返回结构在列表结构上增加命中片段,以便前端复用同一套渲染。

### 前端

- **单页**结构:顶部常驻输入框,下方时间倒序列表。页面加载后输入框自动获得焦点。
- 展开某条 Memo 时**就地展开**,不做路由跳转。展开也由专门的展开图标按钮触发(不再是点击整行,避免干扰折叠态首行文字拖选复制)。展开后是渲染态,**编辑由一个按钮进入**。
  - 原本定的是「点开即可改,不设查看态」,实际用下来推翻了:从 memo 里复制文字是日常动作,而点正文即进编辑会把拖选变成一次点击、选区丢失。后来折叠态整行也是一个大按钮,同样影响了拖选首行文字复制,现折叠展开与进入编辑均收敛为专门按钮。19 要的是不经过两次页面跳转,卡片内的展开/编辑按钮不违反它。
- Markdown 渲染**禁用 raw HTML**。Memo 内容大量来自外部粘贴,而页面脚本可直接访问本机后端;该后端在后续里程碑中将具备执行任意 Python 的能力,这条攻击链必须在此处切断。
- 列表展开状态持久化到 localStorage(`workutil_memo_expanded_ids`),按 memo id 记忆并在挂载时读回,刷新页面后保持展开状态;`SingleMemoPage` 独立管理自身恒展开状态,不共享此持久化。读写均带防御性检查与 try/catch 降级(遵循 i18n 的既有写法)。
- 列表首屏加载最近若干条(固定上限),不做分页与无限滚动。

### 运行与数据

- 服务**只绑定回环地址**。
- 数据目录由平台惯例决定;目录内部只使用**相对路径**,保证整个目录可以被直接拷贝、备份、迁移。
- 数据库文件与图片目录位于**同一个父目录**下,使「拷走整个目录 = 完整备份」成立。

## Testing Decisions

### 什么样的测试是好测试

只测**外部可观察的行为**,不测内部结构。测试应当描述「这个工具对使用者承诺了什么」,而不是「代码内部是怎么组织的」。判据是:重构模块内部实现而不改变对外契约时,测试**不应该**失败。

### 接缝

本仓库尚无任何代码,因此**没有 prior art** —— 这批测试将成为后续所有模块的样板,接缝选择需要谨慎。

**主接缝:HTTP API。** 通过测试客户端驱动真实的应用,配合临时数据目录(临时数据库 + 临时图片目录)。一个接缝覆盖:

- Memo 的创建、读取、编辑、删除
- 搜索,含命中片段的返回
- 图片随正文原子提交、落盘、随 Memo 删除而级联清理
- 列表接口不返回图片内容,只返回数量
- 从正文中移除图片引用后,文件仍然保留(即不做引用计数这一决定的行为体现)

**例外接缝:片段提取纯函数。** 它没有 I/O,而其边界用例矩阵很大(中日文字符截断、英文词边界、多处命中、命中位于首尾、关键词横跨截断边界)。把这个矩阵通过 HTTP 驱动,测试会变得冗长且难读。这是唯一一个低于主接缝的测试点。

### 必须存在的用例

以下用例是 ADR-0002 的**护栏**,防止后来者(包括 AI agent)把子串匹配「优化」成 FTS5:

- 搜索 `バグ` 能命中 `バグ修正`
- 搜索 `中文` 能命中 `中文分词`
- 搜索 `対応` 能命中含该词的正文
- 英文关键词搜索正常工作

前三条在换成 FTS5 后会立刻失败,而只有英文用例的测试套件发现不了这个问题。

### 不测什么

- **HTTP 路由层不单独测试** —— 它只做转发,已被主接缝覆盖。
- **前端 UI 不写自动化测试** —— 第一版界面仍在快速变形,测试会比被测代码更早过期。代价是 UI 回归只能靠手动发现;因为页面数量少且每天在使用,可以接受。界面形态稳定后再补。
  - **一个例外**:Markdown 渲染禁用 raw HTML 这条(见「数据与安全」35)。它不是界面形态,是一条安全边界,而且**只需给 react-markdown 加一个 `rehype-raw` 就会失效** —— 一行改动,人工检查看不出来。这条留一个渲染断言守着。

## Out of Scope

以下均为**刻意排除**,不是遗漏:

| 项目 | 说明 |
| --- | --- |
| 标签 / 归类 | 归类本身是录入负担,与「极低摩擦」冲突。等搜索不够用时再加 |
| 数据导出功能 | 数据目录已可整体拷贝,手动备份可行 |
| 导入现有记事本内容 | 一次性动作,手动复制粘贴即可 |
| 全局快捷键 / 原生入口 | 受浏览器形态限制,需额外的原生程序 |
| 图片缩略图与压缩 | 原图直存;缩略图是性能优化,列表已通过不加载图片规避 |
| 版本历史 / 软删除 | 个人工具无审计需求 |
| 分页 / 无限滚动 | 首屏固定上限已足够 |
| Evidence、文件书签、Todo、Python 脚本 | 属于后续里程碑 |
| 跨机数据同步 | 已决定两台机器数据各自独立(保密考虑) |
| 前端自动化测试 | 见 Testing Decisions |

## Further Notes

### 验收标准是行为,不是功能清单

功能可以全部打勾而工具依然没人用 —— 典型原因是摩擦仍然太高。因此 M1 真正完成的标志是:**连续三天使用,期间没有再打开过记事本。**

### 已知风险

浏览器标签页**无法注册全局快捷键**。实际录入路径是「切到浏览器 → 找到 workutil 标签页 → 输入」,未必快过一直开着的记事本 —— 而「极低摩擦」正是本功能的核心卖点。

第一版接受这个限制,并在浏览器形态内把摩擦压到最低(单页、打开即聚焦、零导航点击)。上面那条行为验收标准正是用来检验这个风险是否真的致命。若真实使用一周后仍嫌慢,补一个极小的原生入口(托盘 + 全局热键,只负责唤起并聚焦)即可 —— 那是增量,不是重做。
